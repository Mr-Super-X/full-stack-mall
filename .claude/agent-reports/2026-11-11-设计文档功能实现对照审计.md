## 四、偏差与裁剪项（2 项偏差 + 1 处文档欠账）

### 偏差 1：自营商品管理（admin）未实现 —— 有记录的裁剪，但基准文档未回改

- **基准承诺**：§6 接口表列 `POST /mall/admin/products`、`PATCH /mall/admin/products/{id}`（阶段 3-4）；§8 页面地图承诺 admin「自营商品管理」页面。
- **实际**：后端无 AdminProductController；admin mall-admin 模块仅 Consignments/Payouts/SeckillActivities 三页，无商品管理页。
- **裁剪依据**：阶段4 spec §11 v1.1 偏差修正明确「admin 商品上架/下架接口本期不建……运营侧约束为 v2，随 admin 商品管理一起做」。
- **欠账**：基准文档自述「实施计划不得与本文档冲突；冲突时先改文档再动手」+ §13 文档同步义务——阶段 spec 反向裁剪基准范围后，基准 §6/§8 未同步标注推迟，违反文档同步义务。
- **影响**：功能演示不受影响（自营商品走 init.sql 种子）；运营闭环缺口已明示 v2。

### 偏差 2：支付回调路径名 alipay/notify → fake/notify —— 命名偏差，功能闭环完整

- **基准契约**：`POST /mall/payments/alipay/notify`；实际实现为 `POST /mall/payments/fake/notify`，并扩展了契约外的 `GET /fake/checkout`（沙箱收银台 HTML 页，FakeProvider 形态的自然产物）。
- **影响评估**：幂等三件套（验签→幂等→状态机单向）在 FakeProvider 落地，买家支付→回调→轮询→订单推进全链路可用；non-goal 明示真实支付宝签约不做。属命名与契约的偏差，非功能遗漏。
- **附带缺口**：§7 决策 #3 预留的 AlipaySandboxProvider 实现位未做（接口 PaymentProvider 在位）。

### 欠账：阶段5 spec smoke 步骤与实际页面的出入

- 阶段5 spec §4.6 冒烟走查写「admin 登录看订单管理」，但 admin 端从无订单管理页面（§8 页面地图未承诺）。smoke 描述与模块实际不符，属 spec 笔误级，不影响交付物。
