**Goal**：卖家侧闭环走通——提交寄卖 → admin 核价/驳回 → 卖家确认定价 → 铸造 Product 上架（商品列表可被买家搜到）；配套地址 CRUD（阶段 2 下半场下单的地址快照来源）。

**Architecture**：新增 `consignment/` 与 `address/` 两个业务包（沿用 Controller → Service → Mapper 分层与构造器注入）；寄卖单状态机用 Service 层显式校验防跳变；**铸造（accept）走 `@Transactional` 四写原子**（product + product_item + product_image + listing 状态）；权限分两层：AuthInterceptor 管身份（扩展保护路径），新增 AdminInterceptor 管角色（`/mall/admin/**` 需 `role=ADMIN`）。

**Tech Stack**：沿用现有（Java 17 / SB 3.5.9 / MP 3.5.18.1 / MySQL 8.4 / jjwt 0.12.6 / 本机 Maven）；无新依赖。

**Spec**：[../specs/2026-11-06-resale-mall-design.md](../specs/2026-11-06-resale-mall-design.md)（§4.2 寄卖单、§4.3 铸造、§5 寄卖状态机、§6 接口契约、§12.1 决策 4 项）

## Global Constraints

- 信封 `Result{code,message,data}` code=200 成功；业务错误 HTTP 仍 200、code 见信封
- 新增错误码：`FORBIDDEN(403,"无权限访问")`、`CONSIGNMENT_NOT_FOUND(404,"寄卖单不存在")`、`CONSIGNMENT_STATE_ILLEGAL(400,"当前状态不允许该操作")`、`ADDRESS_NOT_FOUND(404,"地址不存在")`
- 越权访问他人寄卖单/地址一律按 **404** 处理（不暴露资源存在性，防 ID 遍历探测）
- 寄卖状态机：`SUBMITTED → REVIEWING → PRICED → LISTED → SOLD → SETTLED`，`REVIEWING ↘ REJECTED`；流转前必须校验当前状态，非法流转抛 CONSIGNMENT_STATE_ILLEGAL
- 铸造（accept）四写必须 `@Transactional` 原子；重复 accept 由状态机拦截（PRICED 才可 accept，LISTED 再调即非法流转）
- 图片字段 `images`：入参为 URL 字符串数组（1~9 张），落库 JSON 列；铸造时逐个写入 product_image（sort 递增）
- 地址默认标记：设新默认时同用户旧默认必须同事务清除
- Entity 不出 Controller；单文件 ≤400 行；公共 API 中文 Javadoc
- init.sql 幂等可重跑；本计划重建数据库一次（加列），**验收前执行 `docker compose down -v && up -d`**（演示数据会重置，测试账号需重注册）

## Review Focus（最易咬人的 6 处）

1. **状态机防跳变**：REVIEWING 才能 review、PRICED 才能 accept；对同一寄卖单重复 accept 必须被拦（幂等由状态机兜底）——ConsignmentServiceTest 断言非法流转抛 400
2. **铸造原子性**：四写任一失败整体回滚（如 product_image 插入失败，product 不得残留）——测试用 mock 抛异常验证事务标记存在；e2e 断言铸造后商品出现在列表
3. **越权与探测**：买家身份访问他人寄卖单详情返回 404（不是 403，不暴露存在性）；USER 角色调 /mall/admin/** 返回 403——测试各断言一条
4. **金额精度**：platformPrice/commissionRate/expectedPrice 一律 BigDecimal，禁 double；commission 计算在阶段 3 才用，本计划只存
5. **图片数组校验**：images 为空数组或 >9 张 → 400；非 URL 字符串 → 400
6. **地址归属**：PATCH/DELETE 他人地址返回 404；isDefault=true 时旧默认被清除（同一事务）
