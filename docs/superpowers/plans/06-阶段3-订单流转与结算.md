# 阶段 3 后端实施计划：订单流转 + 卖家订单列表 + Payout 三步结算（2026-11-09）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **执行方式**：主会话逐文件实现（native），每个文件完成后自检并回看本计划；验收环节 curl + 浏览器实操。

**Goal**：运营闭环走通——买家付款后寄卖单自动转"已售出"；卖家在"我卖出的订单"里发货；买家确认收货触发 Payout（卖家应得=成交价×(1-抽佣)）；admin 三步审批（PENDING→CONFIRMED→PAID）打款后寄卖单转"已结算"。阶段 2 落下的售出联动一并补齐。

**Architecture**：订单流转全部走**条件更新状态迁移**（字符串列名 UpdateWrapper，同 plan-04/05 范式：并发只放行一个）；发货权限按订单主体二分——含寄卖件的订单必须卖家本人发（`OrderItem.sellerId == 当前用户`），全自营订单必须 ADMIN（寄卖不能进购物车，订单主体天然单一）；确认收货同事务按寄卖明细生成 Payout（佣金率经 `OrderItem.productItemId → product.id → consignment_listing.listed_product_id` 回联寄卖单）；Payout 三步迁移与寄卖单 SETTLED 联动同在一个 `@Transactional`。

**Tech Stack**：沿用现有（Java 17 / SB 3.5.9 / MP 3.5.18.1 / MySQL 8.4 / jjwt 0.12.6 / 本机 Maven）；无新依赖。

**Spec**：[../specs/2026-11-06-resale-mall-design.md](../specs/2026-11-06-resale-mall-design.md)（§4.5 Payment+Payout 钱的两条线、§5 三条状态机、§6 接口契约（订单 ship/confirm、寄卖管理 settle）、§12.1 决策）

**前置契约**（已交付）：`OrderServiceImpl`（requireOwnedOrder/migrateOrderStatus/loadLines 私有件可复用）、条件更新范式、`ConsignmentListingMapper`、双层拦截器（`/mall/orders/**` 已登录保护、`/mall/admin/**` 已 ADMIN 守卫）。

## Global Constraints

- 信封 code=200 成功；业务错误 HTTP 仍 200
- 新增错误码：`PAYOUT_NOT_FOUND(404,"结算单不存在")`、`PAYOUT_STATE_ILLEGAL(400,"当前结算状态不允许该操作")`
- 订单/结算状态迁移全部走**条件更新**（字符串列名 UpdateWrapper），行数 0 即非法流转——不做内存"读-判-写"
- 卖家/管理员越权：他人资源按 404（探测防护）；角色不符（USER 调 admin、卖家发非本人寄卖件）按 403
- **Payout 幂等**：`uk(order_item_id)` 唯一约束兜底；重复 confirm 已存在 Payout 时跳过（不重复生成、不报错）
- 金额精度：BigDecimal，佣金拆分 `setScale(2, HALF_UP)`；`sellerAmount + commission = price × quantity` 恒等
- 售出联动（LISTED→SOLD）用条件迁移，重复回调/并发下幂等容忍（行数 0 不报错）
- Entity 不出 Controller；单文件 ≤400 行；公共 API 中文 Javadoc

## Review Focus（最易咬人的 6 处）

1. **售出联动幂等**：重复支付回调（并发）同时触发寄卖单迁移——条件更新只放行一次，第二次行数 0 静默容忍（不得影响订单 PAID 主流程）
2. **佣金拆账恒等**：sellerAmount + commission == price × quantity（rate 两位小数边界如 15.00% × 99.00）——OrderServiceImplTest 断言等式成立
3. **重复确认收货**：confirm 调两次 → 第二次 ORDER_STATE_ILLEGAL（状态机拦截），且不得重复生成 Payout（uk 兜底验证）
4. **发货主体混淆**：买家（非卖家）点发货 → 404；卖家 A 发卖家 B 的寄卖件 → 404；USER 角色发自营件 → 403
5. **审批跳级**：PENDING 直接 pay（跳过 CONFIRMED）→ 400 非法流转；PAID 后再次操作 → 400
6. **SETTLED 联动原子性**：Payout PAID 与寄卖单 SETTLED 同事务——联动失败整体回滚，不得出现"钱付了但寄卖单没结算"的中间态
