# 阶段 4a：秒杀业务闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 跑通秒杀全链路——多场并行活动、独立库存池划拨/归还、条件更新防超卖、四错误码齐全，覆盖后端 + h5 + admin 三端。

**Architecture:** `seckill_activity` 表阶段 0 已建（零加表），`orders` 加 `seckill_activity_id` 唯一键兜底限购；创建活动事务内划拨 `product_item.stock`，活动期间只扣独立池（`sold_count` 条件更新），结束/取消惰性归还。下单复用结算页直购路径（query 携 `seckillActivityId`），成功后走既有 FakeProvider 收银台。

**Tech Stack:** Java 17 / Spring Boot 3.5 / MyBatis-Plus / JUnit 5 + Mockito + MockMvc；Vue 3 + Vant（h5）/ Element Plus（admin）/ vitest。

**Spec:** [docs/superpowers/specs/2026-11-10-阶段4-秒杀与搜索设计.md](../specs/2026-11-10-阶段4-秒杀与搜索设计.md)（v1.1，§11 偏差修正已并入）

## Global Constraints

- 后端统一 `Result<T>` 信封；业务异常只抛 `BusinessException(ResultCode)`，禁止 controller/service 手写 try-catch 拼错误响应。
- 受保护路径必须登记 `WebMvcConfig.addInterceptors`（Auth 先于 Admin）；`UserContext` 用 `getRequired()`。
- 建表唯一来源 `backend/sql/init.sql`（幂等 DROP+CREATE、无物理外键、utf8mb4）；金额 `DECIMAL(10,2)` / `BigDecimal`。
- 快照铁律：`order_item.price` 定格 `seckill_price`，任何场景不回联活动表。
- 防超卖只认条件更新（`UPDATE ... WHERE sold_count < seckill_stock`，影响行数 0 即失败），禁止先查后写。
- 新增 `ResultCode`：40001 `SECKILL_NOT_STARTED` / 40002 `SOLD_OUT` / 40003 `LIMIT_EXCEEDED` / 40004 `DUPLICATE_ORDER`（+ 计划内追加 404 `SECKILL_NOT_FOUND`）。
- 限购固化：`limit_per_user` 恒 1，创建时后端校验拒绝 >1。
- 活动挂载约束：仅「单 SKU 自营商品」（`owner_type=PLATFORM` 且 `product_item` 恰一条）。
- commit message 中文、约定式前缀；未经用户同意不 commit（本计划每个 Task 末尾的 commit 步骤需用户确认后执行）。
- 前端：新 composable/store/类型必须带 `.spec.ts`；BEM 规范（`lang="scss"` 禁 scoped、`bem` 单实例）；禁用 `!important`。

## Review Focus

1. **并发双请求同用户同活动**：先查数（40003）都通过时，唯一键 uk_user_activity 必须只有一个成功、另一个得 40004（单测模拟 DuplicateKeyException 路径）。
2. **活动中商品被 SQL 下架**：下单事务第 3 步有 `status=1` 校验，须给 40001 而非 500。
3. **过期活动惰性推进与归还的原子性**：`ENDED` 推进与 `product_item.stock` 归还在同一事务，崩溃不能出现"已 ENDED 未归还"。
4. **关单回补防负数**：`sold_count - 1 WHERE sold_count > 0` 条件更新，回补不得把独立池减到负（负值会让后续抢购多放行）。
5. **划拨透支**：两个活动并发划拨同一批 stock，`product_item` 条件更新（`stock >= N`）只放行一个。
