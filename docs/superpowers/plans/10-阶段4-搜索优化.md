# 阶段 4c：列表搜索优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** keyword 从 LIKE 前导模糊升级为 MySQL ngram 全文索引，列表页搜索增强（历史记录 + 热搜词），`GET /mall/search/hot-words` 上线。

**Architecture:** `product` 表加 FULLTEXT(ngram) 索引；`ProductMapper.xml#selectSummaryPage` 的 keyword 条件改 `MATCH ... AGAINST`（BOOLEAN MODE），应用层转义 BOOLEAN 操作符防语法错误；h5 列表页搜索框输入态（keyword 为空）渲染历史（localStorage）+ 热搜（后端常量），提交后走既有结果列表。

**Tech Stack:** MySQL 8.4（ngram parser）/ Spring Boot / MyBatis-Plus / Vue 3 + Vant / vitest。

**Spec:** [docs/superpowers/specs/2026-11-10-阶段4-秒杀与搜索设计.md](../specs/2026-11-10-阶段4-秒杀与搜索设计.md)（v1.1 §4）

## Global Constraints

- 建表唯一来源 `backend/sql/init.sql`（FULLTEXT 索引写在 product 表定义内，幂等重跑）；
- `ProductListRequest.keyword` 语义不变：Service 层 trim 后为空置 null 跳过条件；
- 新 composable 必须带 `.spec.ts`；BEM 规范；禁用 `!important`；
- mock 双接线（dev rawResponse + prod 内联）保持 `check:mock-wiring` 绿；
- commit 中文约定式前缀，未经用户同意不 commit。

## Review Focus

1. **BOOLEAN 特殊字符**：keyword 含 `+ - * > < ( ) " ~` 时 AGAINST 语法错误或语义跑偏——应用层转义后不得 500（Task 2）。
2. **单字搜索**：ngram token_size=2 下搜「靴」须命中含「靴子」的商品且不报错（验收 Task 6 实测）。
3. **空 keyword / 纯空格**：trim 后为空须跳过 MATCH 条件（全量），不得拼出 `AGAINST('')`（Task 2）。
4. **历史记录并发写**：连续搜两个词，localStorage 上限 10、去重置顶、新词在首位（Task 4 spec）。

### Task 2: MATCH 查询改造 + 转义工具

**Files:**
- Modify: `backend/src/main/resources/mapper/ProductMapper.xml:19-21`
- Create: `backend/src/main/java/com/fullstackmall/shop/product/utils/SearchQuerySupport.java`（执行时确认 product 包内无 utils 目录则放 `product/service` 同层）
- Test: `backend/src/test/java/com/fullstackmall/shop/product/SearchQuerySupportTest.java`；既有 `ProductServiceImplTest` 追加 keyword 用例

**Interfaces:**
- Consumes: `ProductListRequest.keyword`（trim 后置 null 逻辑已在 `ProductServiceImpl.pageProducts:48-53`）。
- Produces:
  - `SearchQuerySupport.sanitize(String keyword): String` —— 去除 BOOLEAN 操作符字符（`"+- *><()"~@` 等）与连续空白，压缩为单空格；sanitize 后为空返回 null；
  - `ProductServiceImpl.pageProducts`：keyword 非 null 时 `request.setKeyword(SearchQuerySupport.sanitize(...))`（sanitize 返 null 则整体置 null 跳过条件）；
  - XML 条件替换为 `AND MATCH(p.name, p.selling_point, p.tag) AGAINST (#{q.keyword} IN BOOLEAN MODE)`。

- [ ] **Step 1: 写失败测试**

`SearchQuerySupportTest`：
1. `"T恤"` → `"T恤"`（不变）；
2. `"牛仔+夹克"` → `"牛仔夹克"`（`+` 去除）；
3. `"  牛皮  靴 "` → `"牛皮 靴"`（压缩空白）；
4. `"+++"` → null；
5. `ProductServiceImplTest` 追加：`pageProducts_keyword经sanitize后为空_按全量查询`（断言最终 request.keyword 为 null）。

- [ ] **Step 2: 跑失败 → 实现工具类 + Service 接入 + XML 改造 → 跑通过**

Run: `cd backend && mvn test -Dtest='SearchQuerySupportTest,ProductServiceImplTest' -q`

- [ ] **Step 3: 真实库验证**
