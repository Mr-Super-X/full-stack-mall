# 阶段 4b：秒杀高并发演进 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 4a 秒杀闭环上落地「配置开关切换三实现（optimistic/pessimistic/redis）+ Redis Lua 预扣 + RabbitMQ 完全异步出单 + 令牌桶限流」，产出三实现对压测对照数据与一致性对照表。

**Architecture:** `seckill.strategy` 配置分派扣减与建单路径；redis 路径为「Lua 预扣 + 受理表同事务落库 + 提交后发 MQ + 消费者事务建单 + DLX 自动回补」；受理表即本地消息表简化形态。pessimistic 为 FOR UPDATE 对照组，仅教学压测用。

**Tech Stack:** Spring Boot 3.5.9 / spring-boot-starter-data-redis / spring-boot-starter-amqp / Redis 7 / RabbitMQ 3.13（management）/ Testcontainers / JMeter

**Spec:** `docs/superpowers/specs/2026-11-10-阶段4b-秒杀高并发演进设计.md`（v1.0，已批准）

## Global Constraints

- 错误码：`SECKILL_UNAVAILABLE(40005, "秒杀服务暂不可用，请稍后重试")`、`RATE_LIMITED(40006, "操作太频繁，请稍后重试")`；40001-40004 语义不回退（spec §3 契约不变量）
- Redis 两 key：`seckill:stock:{activityId}`（关口）、`seckill:order:{activityId}:{userId}`（占位，TTL 900s）；Lua 三分支返回 1/0/-1/-2（spec §4.2）
- 时序纪律：Lua 预扣在 DB 事务外先行；受理记录与后续 DB 写同事务；**MQ 发送必须在事务提交后**；发送失败补偿 INCR + 受理表 FAILED（spec §5.3b）
- 超卖恒等式：`DB sold_count ≤ seckill_stock` 任意时刻成立；`DB sold_count = 成功订单数 = Redis 预扣数 − DLQ 深度 − 受理未出单数`（压测后对账，spec §12.7）
- 建单三步（insertSeckillOrder/buildSeckillLine/insertPayment）抽 `SeckillOrderAssembler` 后，4a 同步路径与 4b 消费者**共用同一代码**（spec §13#10 公平性前提）
- commit 中文约定式（`feat:`/`fix:`/`test:`/`chore:`/`docs:`），一个功能一个 commit，禁止 AI 协作痕迹（项目约束 #11）
- 测试镜像既有包结构：`src/test/java/com/fullstackmall/shop/seckill/` 等；Testcontainers 用于 redis/rabbitmq 集成测试
- 前端：composable ≤80 行、展示组件 ≤200 行、容器 ≤300 行（frontend.md 限额）

## Review Focus

1. **重复消费**：同一消息 requeue 10 次，订单表仍只有一单（幂等查重 + uk 撞线转 40004 ack）——Task 7
2. **预扣后事务回滚的补偿漏洞**：DB 校验/DuplicateKey 失败发生在 Lua 预扣之后，INCR 补偿漏掉即少卖——Task 9
3. **key 自愈重建并发**：两个请求同时遇 key 缺失，SET NX 只一个成功，另一个须重试 Lua 而非误判 40001——Task 5
4. **轮询越权**：user A 轮询 user B 的 orderNo 必须 404/403——Task 10
5. **故障注入误开**：`consumer-simulated-failure-rate` 启动日志 warn 提示、>0 时每次消费都记 warn——Task 7
