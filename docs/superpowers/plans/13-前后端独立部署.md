# 前后端独立部署实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在根目录 `deploy/` 下提供前后端可分别部署、启动、停止、查看日志和备份的 Docker Compose 运维入口，统一通过 `http://10.2.161.161:9088` 访问。

**Architecture:** 复用现有 `frontend/Dockerfile` 与 `backend/Dockerfile`，以两个独立 Compose 项目分别运行 Nginx 前端和 Spring Boot 后端及基础设施。两个项目通过固定外部网络 `mall-deploy-network` 通信；仅前端映射宿主机 `9088:80`，后端保持容器网络内访问。

**Tech Stack:** Docker Compose、Nginx 1.27、Spring Boot 3.5 / Java 17、MySQL 8.4、Redis 7、RabbitMQ 3.13、Bash。

**Spec:** 2026-11-19 本轮对话中用户明确批准的部署方案；现有生产行为以 `frontend/deploy/nginx.prod.conf.template`、根 `docker-compose.yml` 和 `backend/src/main/resources/application.yml` 为基准。

## Global Constraints

- 不修改现有业务源码、既有 Dockerfile、根 `docker-compose.yml` 或用户未提交修改。
- 不提交、不推送 Git；不在仓库中写入真实密钥。
- 仅前端公开 `9088`；MySQL、Redis、RabbitMQ 和后端不映射宿主机端口。
- 默认部署在同一台 Linux 服务器，先启动后端再启动前端；`API_UPSTREAM` 不带尾部斜杠，确保 `/api/` 原样转发。
- 新脚本只操作各自 Compose 项目及 `mall-deploy-network`，备份失败时清理本次产生的残缺文件，不自动删除历史备份。
- 备份与恢复文档必须区分 MySQL 持久数据、Redis/RabbitMQ 运行态和前端镜像，不宣称备份包含未持久化的全量运行状态。

## Review Focus

- 缺失或空白密钥：Compose 渲染必须失败并指出变量，任务 1 用临时空值环境验证。
- 后端未启动时单独启动前端：README 必须明确启动顺序和 `/api/` 临时不可用现象，任务 2 核对文档。
- `/api/` 转发路径：Nginx `proxy_pass` 不得带 URI 部分，任务 2 用渲染后的配置检查。
- 备份中断或目标服务未运行：脚本必须非零退出且不把残缺文件当成功备份，任务 1、2 分别做语法与分支检查。
- 停止与清理边界：脚本不得执行 `down -v`、删除数据卷或清理历史备份，任务 3 检查最终差异。

### Task 1: 后端独立部署与 MySQL 备份

**Files:**
- Create: `deploy/backend/docker-compose.yml`
- Create: `deploy/backend/.env.example`
- Create: `deploy/backend/deploy.sh`
- Create: `deploy/backend/backup.sh`
- Create: `deploy/backend/README.md`

**Interfaces:**
- Consumes: 现有 `backend/Dockerfile`、`backend/sql/init.sql`、后端 `18080` 端口和 `/api` context-path。
- Produces: 外部网络中的服务别名 `backend:18080`；`bash deploy.sh start|stop|restart|status|logs [service...]`；`bash backup.sh` 生成 `backups/mall-YYYYMMDD-HHMMSS.sql.gz`。

- [ ] **Step 1: 编写 Compose 与环境变量契约**

Compose 定义 `mysql`、`mall-redis`、`mall-rabbit`、`backend`，使用命名卷持久化 MySQL、Redis 和 RabbitMQ；基础设施健康后才启动后端。`DB_PASSWORD`、`RABBIT_PASSWORD`、`JWT_SECRET`、`PAYMENT_SECRET` 使用 Compose 必填插值，`.env.example` 对应值为空；CORS 默认值为 `http://10.2.161.161:9088`。

- [ ] **Step 2: 编写启停与备份脚本**

`deploy.sh` 默认执行 `start`，启动前检查 Docker Compose、`.env` 和外部网络；`stop` 只停止容器，不删除卷。`backup.sh` 通过运行中的 MySQL 容器执行 `mysqldump --single-transaction`，压缩到权限受限的 `backups/`，执行 `gzip -t` 验证，失败时删除本次残缺文件。

- [ ] **Step 3: 编写部署与恢复文档**

README 给出首次配置、密钥生成示例、后端启动、健康检查、备份和手工恢复命令；明确 MySQL 初始化脚本只在空数据卷执行、恢复会覆盖同名表、Redis/RabbitMQ 数据不等同于 SQL 备份。

- [ ] **Step 4: 静态验证后端产物**

Run: `bash -n deploy/backend/deploy.sh deploy/backend/backup.sh`
Expected: 退出码 0。

使用临时目录中的非真实测试值执行 `docker compose --env-file <temp-env> -f deploy/backend/docker-compose.yml config --quiet`，预期退出码 0；再以空必填值渲染，预期非零退出且指出缺失变量。

### Task 2: 前端独立部署、Nginx 网关与镜像备份

**Files:**
- Create: `deploy/frontend/docker-compose.yml`
- Create: `deploy/frontend/.env.example`
- Create: `deploy/frontend/nginx/default.conf.template`
- Create: `deploy/frontend/deploy.sh`
- Create: `deploy/frontend/backup.sh`
- Create: `deploy/frontend/README.md`

**Interfaces:**
- Consumes: 任务 1 的 `backend:18080` 与 `mall-deploy-network`；现有前端聚合构建产物 `dist-prod/<app>/`。
- Produces: 宿主机 `9088` HTTP 入口；`bash deploy.sh start|stop|restart|status|logs [service...]`；`bash backup.sh` 生成 `backups/frontend-YYYYMMDD-HHMMSS/`。

- [ ] **Step 1: 编写 Compose 与 Nginx 模板**

Compose 复用 `../../frontend/Dockerfile`，映射 `${HTTP_PORT:-9088}:80`，默认 `API_UPSTREAM=http://backend:18080`，将新模板挂载到官方 Nginx 模板目录。Nginx 保留六应用静态托管、history fallback、安全响应头、哈希资源缓存、SSE 关缓冲和根路径跳转 `/h5/h5-mall`；增加 `/healthz` 供容器健康检查。

- [ ] **Step 2: 编写启停与镜像备份脚本**

`deploy.sh` 与后端保持相同命令契约；启动时自动创建缺失的共享网络。`backup.sh` 要求 web 容器已运行，保存其镜像引用、压缩镜像包、Nginx 模板和 `.env`，校验 gzip，失败时只清理本次备份目录。

- [ ] **Step 3: 编写访问与回滚文档**

README 列出买家端、管理端、API 健康检查地址，说明后端须先运行；镜像回滚使用 `docker image load`，恢复对应标签后通过 `docker compose up -d --no-build --force-recreate` 重建容器，不以普通 `restart` 冒充镜像回滚。

- [ ] **Step 4: 静态验证前端产物**

Run: `bash -n deploy/frontend/deploy.sh deploy/frontend/backup.sh`
Expected: 退出码 0。

Run: `docker compose --env-file deploy/frontend/.env.example -f deploy/frontend/docker-compose.yml config --quiet`
Expected: 退出码 0。

如本机 Docker daemon 可用，使用 `nginx:1.27-alpine` 渲染模板并执行 `nginx -t`，预期配置语法有效；不可用时明确标记未执行。
