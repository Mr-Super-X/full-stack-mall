## 1. 意图与为什么

阶段 4 = **有技术深度的商城**。两条线：

1. **秒杀业务闭环（4a）**：把基准文档预留的 `seckill_activity` 表与契约跑通——多场并行、独立库存池、条件更新防超卖、四错误码齐全。Redis 预扣演进（4b）本期**只留演进位不实现**（见 §9）。
2. **列表搜索优化（4c）**：keyword 从 `LIKE '%kw%'`（前导模糊不走索引）升级为 MySQL 8.4 `ngram` 全文索引，并新增搜索页（历史/热搜/结果）。

**为什么先做业务闭环不上 Redis**：防超卖的正确性由数据库条件更新保证（基准文档贯穿决策 #2），Redis 是吞吐演进不是正确性前提；先把业务形态与四错误码跑通，4b 的压测与预扣才有真实场景可验证。

## 3. 秒杀设计（4a）

### 3.1 数据模型（零迁移）

`seckill_activity` 表已于阶段 0 建成（`backend/sql/init.sql` §玩法域），本期**不加表只加一列**：

```
seckill_activity: id / product_id / seckill_price / seckill_stock（独立池）
                  / sold_count / start_time / end_time / limit_per_user / status
orders 新增:       seckill_activity_id BIGINT DEFAULT NULL COMMENT '秒杀场次，普通单为 NULL'
                  + UNIQUE KEY uk_user_activity (user_id, seckill_activity_id)
```

**唯一键语义**：MySQL 唯一索引允许多个 `NULL`，普通订单（`NULL`）互不影响；同一用户同一活动至多一单。下单前先查数给 40003（体验层），并发双请求由唯一键撞线给 40004（并发兜底）——两个错误码各有触发路径，保证四码齐全。

**活动挂载约束（实现级裁决）**：`product_id` 是商品级，但价格/库存在 `product_item`。裁决：**秒杀活动只允许挂在「单 SKU 自营商品」上**——创建时校验 `owner_type=PLATFORM`、`product_item` 恰好一条记录、划拨量 ≤ 该 item 现存 stock。多 SKU 商品参与秒杀是 v2 话题（需活动条目子表），本期拒绝并给出明确错误提示。

**限购固化（实现级裁决）**：本期 `limit_per_user` 恒为 1——admin 创建时后端校验只接受 1（>1 报参数错误），字段保留 DDL 与展示位。原因：`uk(user_id, seckill_activity_id)` 唯一键限定"一人活动一单"，与 >1 限购语义冲突；放开限购需将并发兜底改为累计校验 + 行锁，留 v2。

### 3.2 状态机与时间窗

```
PENDING ──(start_time 到达，查询时惰性推进)──▶ ACTIVE ──(end_time 过期，查询时惰性推进)──▶ ENDED
PENDING ──(admin 取消)──▶ CANCELLED（归还全部划拨库存）
```

- **无调度器**：一切状态推进由查询/写入路径惰性触发（与惰性关单同一哲学，基准文档贯穿决策 #1）。
- **划拨与守恒**：创建（PENDING）时事务内 `product_item.stock -= N` 且插活动行；`ACTIVE/ENDED` 期间秒杀下单**只动独立池**（`sold_count`），不碰 `product_item`——活动库存与常规库存生命周期解耦（基准文档 §11.3）。
- **归还**：`ENDED` 惰性推进的同一事务内，`product_item.stock += (seckill_stock - sold_count)` 归还未售部分；`CANCELLED` 归还全部 `seckill_stock`。归还用条件更新防并发双还。

### 3.3 接口契约

| 接口 | 说明 |
|------|------|
| `GET /mall/seckill/active` | 匿名。返回 `{ live: [...], upcoming: [...] }`：live = 进行中场（含商品摘要：主图/标题/秒杀价/原价/sold_count/seckill_stock/end_time）；upcoming = 未开始场（start_time，最多 5 条） |
| `POST /mall/seckill/{activityId}/orders` | 登录态。入参 `{ addressId, productItemId }`（`productItemId` 须为该活动挂载商品的唯一 SKU，quantity 恒 1 忽略入参；`addressId` 由前端结算页选好带出，见 §5.3 下单路径）。成功 `{ orderNo, paymentNo }` → 前端直跳收银台 |
| `GET /mall/admin/seckill-activities?status=` | admin。分页列表（含商品标题、库存进度） |
| `POST /mall/admin/seckill-activities` | admin。创建：划拨校验后插 PENDING |
| `POST /mall/admin/seckill-activities/{id}/cancel` | admin。仅 PENDING 可取消，归还库存 |

**受保护路径登记**：`/mall/seckill/*/orders` 与 `/mall/admin/seckill-activities/**` 加入 `WebMvcConfig.addInterceptors`（Admin 拦截器挂 admin 前缀，Auth 拦截器挂 orders 写路径）。

### 3.4 下单事务（`POST /mall/seckill/{id}/orders` 执行序）

```
1. 查活动（不存在 → 业务错误"活动不存在"）
2. 惰性推进：未开始 → 40001 SECKILL_NOT_STARTED；已过期 → 同事务置 ENDED + 归还 → 40001
3. 挂载校验：活动商品须单 SKU 自营、item 匹配、且商品 status=1 在售（活动中被下架 → 40001 视作不可售）
4. 限购：count(orders where user_id + seckill_activity_id) ≥ 1 → 40003 LIMIT_EXCEEDED
5. 扣独立池：UPDATE seckill_activity SET sold_count = sold_count + 1
   WHERE id = ? AND sold_count < seckill_stock → 影响行数 0 → 40002 SOLD_OUT
6. 建单（单事务）：orders(type=SECKILL, seckill_activity_id, payAmount=seckill_price)
   + order_item(price=seckill_price 快照——快照铁律，见基准文档 §4.4)
   + payment CREATED；撞 uk_user_activity → 40004 DUPLICATE_ORDER
7. 返回 { orderNo, paymentNo }
```

- **防超卖正确性**：第 5 步条件更新是唯一关口，`sold_count < seckill_stock` 原子保证，200 线程抢 10 件恰好 10 单（验收 §8）。
- **惰性关单联动**：现有超时关单回补 `product_item.stock` 的分支，秒杀单改回补独立池（`sold_count - 1 WHERE sold_count > 0`）。**占位不释放**：关单后唯一键仍在，用户不可重抢——MVP 取舍（防脚本反复占坑），spec 固化为行为。
- **不实现限流**（本期裁剪）：基准文档 §6 精讲契约的"限流"步骤属 4b 最终形态。

### 3.5 错误码（`ResultCode` 新增）

| code | 枚举 | 触发 |
|------|------|------|
| 40001 | `SECKILL_NOT_STARTED` | 未开始 / 已结束 / 已取消 |
| 40002 | `SOLD_OUT` | 独立池扣减影响行数 0 |
| 40003 | `LIMIT_EXCEEDED` | 达限购上限（先查数） |
| 40004 | `DUPLICATE_ORDER` | 唯一键 uk_user_activity 撞线 |

## 4. 搜索优化（4c）

### 4.1 后端

- **DDL**：`product` 表加 `FULLTEXT KEY ft_search (name, selling_point, tag) WITH PARSER ngram`（`ngram_token_size` 用 MySQL 8 默认 2，中文二元组；单字经 BOOLEAN MODE 亦可命中）。
- **查询改造**（`ProductMapper.xml#selectSummaryPage`）：`keyword` 条件由 `p.name LIKE CONCAT('%',#{kw},'%')` 改 `MATCH(p.name, p.selling_point, p.tag) AGAINST(#{kw} IN BOOLEAN MODE)`；空 keyword 跳过逻辑不变；`AGAINST` 遇特殊字符（`+-*><` 等 BOOLEAN 操作符）由应用层转义（空格替换非法字符）防语法错误。
- **热搜**：`GET /mall/search/hot-words` 匿名，返回后端常量数组（8~10 词，运营位；接入配置中心是 v2 事）。
- 列表/搜索共用 `pageProducts`，keyword 语义升级对现有调用方（首页"限时甄选"等不 keyword 的区块）零影响。

### 4.2 h5 列表页搜索增强（不新建独立搜索页）

**修正说明**（v1.1）：列表页已有 `van-search` 搜索栏 + keyword 响应式查询（`views/list.vue`），独立搜索页与之重复。改为输入态增强：

- 搜索框为空（输入态）：结果区位置显示**历史记录区**（localStorage `mall:search-history`，上限 10 条，可清空）+ **热搜词区**（chips，点击即搜）；
- 输入提交后：显示搜索结果列表（既有能力），历史自动去重置顶写入；
- 无新路由、无新页面——列表页即搜索页（主流电商形态）。

`useSearchHistory` composable：读写 localStorage + 去重 + 上限裁剪，带 spec。

## 5. h5 前端设计

### 5.1 首页秒杀区块

`HomeContentDTO` 新增 `seckill` 区块：`{ title, live: SeckillCard[], upcomingCount }`。live 最多 2 场——按单商品挂载约束（§3.1），每场一张商品卡（主图/标题/秒杀价/划线原价/进度条/倒计时），区块头「全部」→ 会场页。首页现有"限时甄选"（discountOnly 伪秒杀）**保留不动**——真秒杀场与运营折扣区并存，数据模型上互不冲突。

### 5.2 秒杀会场页 `/h5-mall/seckill`

van-tabs 两页：`抢购中`（场卡片：商品图/标题/秒杀价/原价/进度条/距结束倒计时，点击进入详情）与 `即将开始`（场卡片 + 距开始倒计时 + start_time）。无数据空态引导回首页。

### 5.3 详情页秒杀插件（基准文档 §8 玩法插件落地）

`GET /mall/products/{id}` 出参加 `activeSeckill`（生效中活动：秒杀价/结束时间/进度/限购）。当 `activeSeckill` 存在时购买区变形：

- 价格区：秒杀价大字 + 原价划线 + 「限时秒杀」徽标；
- 标题下：倒计时横幅（距结束，秒级刷新）+ 抢购进度条（`sold_count/seckill_stock`）；
- 操作区：「立即抢购」按钮 → **跳结算页（复用寄卖直购路径）**：携 `seckillActivityId` 进入 checkout 的秒杀 DIRECT 模式（地址选择/新建、金额展示全部复用现有结算页基建），结算页提交时调秒杀下单接口；规格选择器隐藏（单 SKU 裁决）；后端 `addressId` 由结算页选好带出，**不做**"详情页取默认地址直下单"——避免在详情页重造地址选择能力；
- 活动结束/售罄：倒计时归零显示「已结束/已抢完」并禁用按钮。

倒计时组合式 `useCountdown(target)`：单文件 composable（≤80 行），setInterval 1s + onUnmounted 清理，页面多处复用（会场卡片/详情横幅）。

### 5.4 接口与状态

- `apis/modules/seckill.ts`：`fetchActiveSeckills()` / `placeSeckillOrder(activityId, payload)`；mock 处理器对齐商城 DTO 形状（`check:mock-wiring` 保持绿）。
- 下单成功跳收银台：复用现有 FakeProvider 收银台协议（`paymentNo` 轮询回跳），零新增。

## 8. 验收标准（实现 Agent 不可见，独立测试依据）

1. **四错误码**：未开始/已结束 → 40001；独立池耗尽 → 40002；达限购 → 40003；并发重复下单 → 40004（各给独立用例）。
2. **并发不超卖**：200 线程抢 10 件库存，恰好 10 单成功、其余 40002，`sold_count=10` 且无超扣（`sold_count ≤ seckill_stock` 恒成立）。
3. **库存守恒**：创建划拨 N → 活动期间 `product_item.stock` 少 N → 结束归还 `seckill_stock - sold_count`；取消归还 N。
4. **关单回补**：秒杀单超时关单后 `sold_count` 回落 1，库存可再被抢；同一用户重抢撞唯一键得 40004。
5. **搜索**：搜「T恤」命中含「T 恤」商品（ngram 分词）；单字搜索不报错；空 keyword 回退全量；非法 BOOLEAN 字符不 500。
6. **快照铁律**：秒杀订单 `order_item.price` = 下单时 `seckill_price`，活动结束/改价后不回联。
7. **活动中商品保护**：挂载商品被下架（SQL/未来接口）后下单得 40001（下单事务含 status 校验）；admin 下架拦截接口为 v2（本期无商品管理接口可挂）。
8. **限购固化**：创建活动传 `limit_per_user > 1` 被后端拒绝；正常流程第二单（并发撞唯一键）得 40004。

## 10. 我的裁决清单（builder 无需追问）

| # | 裁决 | 理由 |
|---|------|------|
| 1 | 活动挂商品级、强制单 SKU | 基准表结构如此；多 SKU 需条目子表，v2 |
| 2 | uk(user_id, seckill_activity_id) 作并发兜底 | 基准 §6 明示；NULL 多值语义天然兼容普通单 |
| 3 | 关单不释放购买资格 | 防占坑脚本；体验损失在 MVP 可接受 |
| 4 | 秒杀期间常规库存不动，只扣独立池 | 基准 §11.3 生命周期解耦 |
| 5 | 搜索增强复用列表页既有搜索栏，不新建独立搜索页路由 | 列表页已有 van-search + keyword 查询，独立页重复（v1.1 修正） |
| 6 | 热搜词后端常量 | 无真实搜索日志，统计是 v2 |
| 7 | 首页"限时甄选"与秒杀场并存 | 运营折扣与秒杀是两种业务，模型不冲突 |
| 8 | ngram 默认 `token_size=2` | MySQL 8 默认；单字场景 BOOLEAN MODE 兜底 |
