## 1. 意图与 Why

两个阶段目标的共同指向：让「面试官/技术评估者」在 10 分钟内完成" clone → 一条命令跑起来 → 看到证据链"的完整闭环。

- **部署形态**：用户拍板 docker-compose 本地起全栈（不引入云服务器）。应用本体（Spring Boot JAR）此前从未容器化——backend/docker-compose.yml 只有开发态三件套（mysql/redis/rabbitmq），应用靠本机 `mvn spring-boot:run`。阶段 5 补齐容器化闭环。
- **README 受众**：招聘场景。现有 README 骨架已不错（核心洞察/技术栈/阶段路线/演示账号），但 4b 刚产出的三层证据链（对照实验/一致性/取舍声明）完全没进主 README——这是本项目最大的差异化亮点，必须上黄金一页。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 根目录 `docker compose up -d` 一键起全栈：web(nginx 托管 6 app 产物 + /api 反代) + backend(JAR) + mysql + redis + rabbitmq，对外仅暴露 8080。
2. 浏览器开 `http://localhost:8080/` → 302 → `/h5/h5-mall` 买家端，登录/下单/秒杀全链路可用（真实会话，非 mock）。
3. 主 README 重构为招聘场景黄金一页：顶部技术亮点区嵌入 4b 压测关键数字 + 取舍金句 + 真实截图；快速开始改为一条 compose 命令。
4. 截图素材入库（git 跟踪）：h5 买家链路 + admin 后台 + 秒杀场景，Playwright 在全栈容器上实际截取。

**非目标**

- 云服务器/CI/CD/域名 HTTPS（docker-compose 单机形态已拍板；compose 文件本身即"可上云"的交付物，README 说明改 `API_UPSTREAM` 即可迁移）。
- 前端镜像 app 裁剪（用户拍板 6 个全保留，findBuildableApps 全自动发现）。
- 开发态工作流不变（backend/docker-compose.yml 三件套 + mvn 本机跑保留）。
- 不删模板遗留 app 目录（portal/big/docs）与 h5 内 h5-demo 模块（保守不动）。

**反目标**

- README 变成"什么都有"的流水账——招聘场景 10 分钟注意力，必须分层：黄金一页 → 深读链接。
- 为部署引入新依赖/新框架（K8s/helm 等）——docker-compose 是拍板形态，KISS。
- 截图造假——所有截图必须来自真实运行的全栈容器（Playwright 截取）。

## 4. 方案设计

### 4.1 后端 Dockerfile（新建 backend/Dockerfile）

```
阶段 1 build：maven:3.9-eclipse-temurin-17
  COPY pom.xml + src → mvn -DskipTests package（surefire 全量 209 个用例不进镜像构建，
  构建期跑测试会让镜像构建 10min+；测试门禁在 CI/本地 mvn verify 已承担——ledger 教训：
  gh-pages 三连坑"Docker 内重复跑无收益"同理）
阶段 2 runtime：eclipse-temurin:17-jre-alpine（jre 非 jdk，alpine busybox 提供 wget）
  非 root 用户运行、EXPOSE 18080、HEALTHCHECK 用 `wget -qO- http://127.0.0.1:18080/api/mall/product/list`
  （builder-check 修正：actuator 未引入且该端点已核实匿名可访问——WebMvcConfig 拦截名单不含它；
  alpine 无 curl，须用 busybox wget）
```

镜像名 `mall-backend:prod`，容器网络内服务名 `backend`，web 反代 upstream `http://backend:18080`。

### 4.2 根目录 docker-compose.yml（新建）

```yaml
services:
  mysql:    # 形态沿用 backend/docker-compose.yml 三件套配置（init.sql 挂载路径为 ./backend/sql/init.sql）
  mall-redis:    # 同上
  mall-rabbit:   # 同上 + builder-check 关键修正（见下）
  backend:
    build: ./backend
    depends_on: { mysql: condition: service_healthy, mall-redis: service_healthy, mall-rabbit: service_healthy }
    environment:   # 容器网络服务名注入（对齐 yml 的 ${VAR:default} 占位）
      DB_URL: jdbc:mysql://mysql:3306/mall?...   # 容器内 3306 非宿主机 13306
      REDIS_HOST: mall-redis
      RABBIT_HOST: mall-rabbit
      RABBIT_USER: mall          # builder-check 修正：guest 被 rabbitmq loopback_users 禁远程，
      RABBIT_PASSWORD: mall      # 容器网络内必 ACCESS_REFUSED——compose 建 mall/mall 用户 + 注入覆盖
      SECKILL_STRATEGY: optimistic   # 默认值，README 说明 SECKILL_STRATEGY=redis up 可体验完整演进
      JWT_SECRET: <同 yml 教学默认值>  # 显式写出 + 注释"生产必须改"
      PAYMENT_SECRET: <同上>
    # 不暴露端口到宿主机（web 容器内反代即可）；调试可临时加 ports 18080:18080
  web:
    build: ./frontend
    ports: ['8080:80']
    environment: { API_UPSTREAM: http://backend:18080 }
    depends_on: { backend: condition: service_started }
```

> **RabbitMQ 用户创建**：mall-rabbit 服务加 `RABBITMQ_DEFAULT_USER=mall` / `RABBITMQ_DEFAULT_PASS=mall`，
> 首启即建用户（替代 guest）；yml 侧零改动（`${RABBIT_USER:guest}` 被环境变量覆盖）。
> 开发态 backend compose 的 guest 走宿主机 loopback 不受影响。

关键语义：

- **单一对外口 8080**：mysql 13306/redis 5672 等仅容器网络（生产形态安全基线；调试用 `docker compose exec` 进容器）。
- **种子数据**：init.sql 全量保留——含 4b 压测 500 账号（perf001-500/admin123）+ 活动 18（10 件库存 NOW() 时间窗）。**这是特性不是残留**：README 演示秒杀开箱即用；benchmark/README.md 账号池引用保持真实。
- **backend/docker-compose.yml 不动**：开发态照旧（mvn 本机跑 + 13306 直连）。两份 compose 并存，README 快速开始区分"体验全栈（根 compose）"与"开发调试（backend compose）"。

### 4.6 验证方案

1. **构建**：`docker compose build`（首次含前端 pnpm install + 6 app 构建，预计 5-10min；后端 mvn package ~2min）。
2. **全栈 smoke**：`docker compose up -d` → 等待 healthy → 浏览器走查：h5 首页加载真实商品 → buyer 登录 → 下单链路（购物车→结算→模拟支付）→ 秒杀活动 18 下单（optimistic 态）→ 我的订单可见 → admin 登录看订单管理。**每步失败按 systematic-debugging 定位，不打补丁**。
3. **策略切换回归**：`SECKILL_STRATEGY=redis docker compose up -d` 重建 backend → 秒杀下单走受理表路径 → 恢复 optimistic。
4. **截图**：smoke 通过后 Playwright 实截 §4.5 六张。
5. **收口**：CHANGELOG 落字、git status 自查、README 终读（招聘视角 10 分钟演练）。

## 6. 取舍声明（设计层）

1. **镜像构建不跑测试**：Docker 内 mvn package 加 `-DskipTests`。209 后端用例 + 142 前端用例已在本地 mvn/pnpm 全绿，镜像构建跑测试 10min+ 且与 gh-pages 教训同源（"Docker 内再跑一遍无收益反而拖慢"）。构建可复现性由 `--frozen-lockfile`（前端已有）+ 锁定 base image digest 保障。
2. **教学密钥默认值显式写进 compose**：JWT_SECRET/PAYMENT_SECRET 在 compose environment 显式给教学默认值 + 注释"生产必须改"。不假装安全，也不为多环境密钥管理引入 vault——单机教学项目的诚实边界。
3. **压测种子数据保留**：500 压测账号 + 活动 18 在 init.sql 保留。删除会让 benchmark/README.md 的账号池引用失真；保留 + README 注明用途是更诚实的处理。
4. **后端不暴露宿主机端口**：调试成本（docker compose exec）换生产形态安全基线（单对外口）。需要本机直连调试时临时加 ports，README 注明。

## 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 前端 6 app 构建在 Docker 内首次超时/内存不足 | .dockerignore 已排除 node_modules；构建失败则调 Docker Desktop 内存上限（README FAQ） |
| 容器网络内 DB host 切换遗漏某处（yml 默认值 localhost） | compose 显式注入 DB_URL/REDIS_HOST/RABBIT_HOST 全覆盖；MessagingConfigBindingTest 已有顶层绑定回归 |
| nginx 302 改后丢端口（$http_host 逻辑） | 沿用模板既有 `$scheme://$http_host` 形态，只换路径段 |
| Playwright 截图依赖浏览器已装 | `playwright install chromium` 前置步骤 |
| 全栈 compose 与开发 compose 端口冲突（都起时 13306/6379 撞） | 根 compose 不暴露基础设施端口 ✅ 天然规避；README 说明两形态互斥或共存条件 |
| RabbitMQ 管理台截图与"仅暴露 8080"矛盾（15672 不映射宿主机） | 截图环节临时 `ports: ['15672:15672']`，截完撤下（builder-check 补充） |
| README 压测数字落字失真 | 实施时以 benchmark/README.md 实测矩阵为准逐字核对（builder-check 补充） |
| 回滚 | 全部新增文件（Dockerfile/根 compose）零侵入存量代码；README/nginx 模板为 Edit 可逐行回退；git 分支在 develop，失败直接 revert |
