# 任务：以 full-stack-mall 掌握 Spring Boot 后端与 Docker Compose 部署

## 为什么

学习者具备前端开发经验，但没有独立搭建后端项目的经验。目标是以当前仓库为真实教材，从零建立对后端运行、业务实现和部署运维的掌控，而不是只积累面试术语。

原“面试讲清项目”的目标保留为次级成果：能解释架构决策，更要有可运行、可验证和可恢复的证据支撑。

## 成功看起来是什么样的

- 能区分本地开发与全栈容器两种形态，独立启动并验证当前项目。
- 能闭卷画出请求、鉴权、下单、支付和部署链路，指出对应代码与配置。
- 能完成一个经过人工验收标准约束的纵向小需求，并解释各层修改原因。
- 能运行已有测试、观察日志、构造失败场景，并根据证据定位问题。
- 能在本地或一次性测试环境完成构建、部署、备份验证、恢复和回滚。
- 能明确说明健康检查、测试、备份和业务验收各自的边界。

## 当前基础与进度

- 前端开发经验已披露；后端搭建经验为零，不预设 Java Web、Spring 或 Docker 先验知识。
- 第 1～8 课已交付，但既有记录显示测验答案未完整回收，全部保持“掌握待验证”。
- 第 9 课“全栈运行与部署地图”已交付，作为新路线的当前课。
- 完整学习循环见 `README.md`，阶段路线见 `LEARNING-ROADMAP.md`。

## 约束条件

- 以本仓库真实代码、配置和部署脚本为主教材，代码事实必须引用文件与行号。
- 框架行为以 `RESOURCES.md` 收录的一手文档为准，不依赖未经核验的参数化记忆。
- 每次只教一个范围明确的小问题；先预测、再实验、后教回，不用重复阅读代替掌握。
- 实验默认在本地或一次性测试环境进行；真实服务器、停止写入、恢复和破坏性命令需单独确认。
- 不在学习材料、日志反馈或 Git 中记录真实密钥、Cookie、令牌和业务敏感数据。

## 范围之外

- 基础验收前不扩展 Kubernetes、微服务拆分、服务网格和 JVM 深度调优。
- 不为“显得高级”引入当前任务不需要的框架、中间件或部署平台。
- 不把课程交付、测试全绿、容器运行或备份文件生成单独视为完整验收。
