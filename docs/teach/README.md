# full-stack-mall 后端与部署学习工作区

> 这是本仓库唯一的 `teach` 学习入口。目标不是“把课程看完”，而是让学习者能独立启动、读通、修改、验证、部署、排障和回滚当前项目。

## 4. 每节课的完整学习循环

```text
确定本课目标
  ↓
合书预测：先画链路 / 写预期，不立即看答案
  ↓
学习短课：只处理一个范围明确的问题
  ↓
提取练习：先独立作答，再查看解析
  ↓
真实实验：一次只改变一个变量，保留命令和输出
  ↓
教回：用自己的话解释正常、失败、恢复三条路径
  ↓
向 AI 反馈：答案 + 置信度 + 实验结果 + 自己的解释
  ↓
AI 评价证据 → 写学习记录 → 补练或生成下一课
  ↓
间隔复习：不看课程重新提取，而非重复阅读
```

### 开始一课

1. 教师先读取 `MISSION.md`、`RESOURCES.md`、本看板和最近相关学习记录。
2. 学习者先写下对本次问题的预测；不知道也可以写“不知道”，禁止先翻答案拼凑。
3. 课程只引入完成当前任务所需的概念，不顺带扩张到整个框架。
4. 实操默认在本地或一次性测试环境进行；真实服务器、数据恢复和破坏性命令必须单独确认。

### 完成一课

只有以下四类证据齐备，才可把“掌握状态”改为“已通过”：

| 证据 | 通过表现 |
| --- | --- |
| 提取 | 不打开课程，能画出本课链路并解释关键术语 |
| 应用 | 完成本课实验，提供真实命令、关键输出与预期对照 |
| 排障 | 能解释至少一个失败场景，并指出定位路径 |
| 迁移 | 面对一个相近的新场景，能预测行为并说明依据 |

答错题不需要“重看一遍就算完成”。教师应换一个场景重考同一概念，再决定是否进入下一课。

## 5. 每节课后的反馈格式

把下面模板复制给 AI；没有执行的步骤明确写“未执行”，不要用预期冒充结果。

```text
我正在学习 docs/teach/ 的 full-stack-mall 后端与部署课程。

课程：第 __ 课，________
我的测验答案：1.__ 2.__ 3.__ 4.__
我最不确定的是：________

实验状态：已执行 / 部分执行 / 未执行
执行环境：本机 Docker / 本机 Maven / 测试服务器 / 其他
我最初预测：________
实际结果：________
关键命令与输出：
________

请按以下顺序指导我：
1. 先评价我的答案和解释，不要直接跳到下一课。
2. 区分代码已确认事实、实验已验证事实和仍未验证的推测。
3. 针对错误或不稳的概念，用一个新场景让我再答一次。
4. 若证据足够，更新学习记录；若不足，明确缺什么证据。
5. 给出一次短复习任务，再决定下一课。
```

不要粘贴真实 `.env`、密码、JWT、Cookie、服务器私钥或完整业务数据。`docker compose config` 的完整输出也可能展开敏感配置，反馈时只摘取与问题有关的非敏感片段。

## 6. AI 教师的固定职责

### 学课前：诊断

- 根据现实目标和学习记录选择最近发展区，不机械按编号续课。
- 如果目标和范围不清，先澄清；不要替学习者虚构验收标准。
- 课程所需知识必须来自仓库事实或 `RESOURCES.md` 中的可信来源。

### 学课中：教练

- 优先追问：“你预计会发生什么？依据是哪段配置或代码？”
- 用前端经验作类比时，同时指出类比失效的边界。
- 一次只引入一个主要难点，知识学习不故意增加难度，技能提取则保留必要难度。

### 学课后：验收与记录

- 不因学习者说“懂了”就记录为掌握；需要可观察证据。
- 学习记录只写先验知识、已证明理解、误解修正和目标变化，不写逐节课流水账。
- 学习者能正确使用一个术语后，才把它加入 `GLOSSARY.md`。
- 下一课使用当前最大未占用编号；不得覆盖既有课程或学习记录。
- 旧理解被新证据推翻时，用 `Status: superseded by LR-NNNN` 标记旧记录，不删除历史。

## 7. 间隔复习与交错练习

默认复习节奏为首次学习后 **1、3、7、14 天**，可按实际掌握情况调整。复习必须闭卷开始：

| 时间 | 任务 |
| --- | --- |
| 第 1 天 | 重画本课链路，复述正常／失败／恢复路径 |
| 第 3 天 | 做一个改变单一条件的新实验，先预测再执行 |
| 第 7 天 | 混合两道旧课问题，避免只会按课程顺序回忆 |
| 第 14 天 | 向 AI 做五分钟“教回”，由 AI 追问证据和边界 |

连续两次能正确提取并迁移，才可降低复习频率。答错则缩短间隔并回到相应实验，不靠重复阅读制造熟悉感。

## 9. 实验安全边界

- `stop`、`start`、`restart`、`down` 和 `down -v` 不是同义词；先查[运维速查表](./reference/compose-runbook.html)。
- **不要把 `docker compose down -v` 当普通重启。**它会删除 Compose 声明的命名卷；只有明确要永久重置可丢弃的本地数据时才考虑使用。
- 修改 `init.sql` 不会自动更新已有数据库；不要为了“让 SQL 生效”直接删除含重要数据的卷。
- 备份不等于可恢复。恢复练习只在一次性测试库进行，先验证备份，再讨论真实环境恢复。
- 真实部署、停止写入、数据恢复和回滚均属于高影响操作；学习材料中的命令不等于已获执行授权。
- 生产密钥只走未入库的环境配置，课堂反馈不得包含真实密钥。
