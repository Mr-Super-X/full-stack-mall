full-stack-mall 后端课 · Lesson 1

一次请求的完整旅程

本课收获：当浏览器发出 GET /mall/product/list，你能指着代码讲出它途经的每一站、谁把它拦住、谁给它打包回家。这是面试讲解项目的地基。

0先建立一张地图

这个后端按业务域分包：product（商品）、user（用户/鉴权）、cart（购物车）、order（订单）、payment（支付）、payout（结算）、seckill（秒杀）、consignment（寄卖）。每个域内部再分四层，这是 Java Web 的经典分层：

四层速记：Controller 接客 → Service 算账 → Mapper 取货 → 数据库落账。Guest 只跟 Controller 说话，Controller 只跟 Service 说话，谁都不许越级。

程序从 ShopApplication.java:15 的 SpringApplication.run(...) 启动——它撑起一个内嵌的 Tomcat 服务器，从此守在 18080 端口等请求上门。

1第一站：拦截器——进门安检

请求到达后、Controller 之前，会先过一道安检。安检名单注册在 config/WebMvcConfig.java:29-39：

// 注册顺序即语义：Auth 先解析身份写 UserContext，
// Admin 后读上下文校验角色
registry.addInterceptor(new AuthInterceptor(jwtService, cookieName))
    .addPathPatterns("/mall/auth/me", "/mall/cart/**", "/mall/orders/**", ...)
    // 支付回调与模拟收银台：无用户 Cookie，鉴权靠验签，放行
    .excludePathPatterns("/mall/payments/fake/notify",
                         "/mall/payments/fake/checkout");

backend/src/main/java/com/fullstackmall/shop/config/WebMvcConfig.java:29-39

两个关键设计，都是面试会被追问的点：

1

路径黑白名单

首页、商品列表这类匿名可逛的接口刻意不挂拦截器（名单里没有 /mall/product/**）；购物车、订单等必须登录。而支付回调 /fake/notify 是"支付宝"服务器来调用的，它手里没有用户的登录 Cookie——所以排除，改由验签证明身份。

2

UserContext 用完必须擦

@Override
public void afterCompletion(...) {
    UserContext.clear();  // 红线：Tomcat 线程复用，不清理则下一请求读到上一用户
}

user/interceptor/AuthInterceptor.java:42-46

解析出的用户身份放在 UserContext（基于 ThreadLocal——可以理解成"当前线程的口袋"）。Tomcat 的线程是复用的：这单生意做完，线程不销毁，直接去接待下一位客人。口袋不擦，下一位客人就会摸到上一位的身份证。

2第二站：Controller——接单窗口

过了安检，请求按 URL 被分发到对应的 Controller。以商品列表为例，product/controller/ProductController.java:29-32：

@GetMapping("/list")
public Result<PageResult<ProductSummaryDTO>> list(
        @Valid @ModelAttribute ProductListRequest request) {
    return Result.success(productService.pageProducts(request));
}

backend/src/main/java/com/fullstackmall/shop/product/controller/ProductController.java:29-32

注意 Controller 有多"瘦"：它不查库、不算价，只做两件事——① 把 URL 路径和 ?page=1&categoryId=3 这类查询串翻译成 Java 对象（@ModelAttribute）；② 调用 Service，把结果包进 Result.success(...)。这就是面试常说的"瘦 Controller"。

3第三、四站：Service → Mapper → 数据库

ProductService 里写业务规则（分页逻辑、筛选条件组装）；ProductMapper 是一个 MyBatis-Plus 接口，方法调用最终变成 SQL 发给 MySQL。这两层是后续课程的主战场——今天只需要知道：所有"规矩"都住在 Service，所有"取数"都住在 Mapper。

4回家路上：统一信封与异常兜底

Controller 返回的 Result 是统一响应信封（common/Result.java:9-13）：

// 与前端 packages/shared/src/api/http.ts 约定一致——
// code=200 为成功，data 承载业务数据
public class Result<T> {
    private int code;     // 业务码：200 成功，其余见 ResultCode
    private String message;
    private T data;
}

前端不用猜每个接口返回什么形状——永远是 {code, message, data}。业务失败（如"商品不存在"）时 Service 抛出 BusinessException，由 GlobalExceptionHandler（common/GlobalExceptionHandler.java:28-37）翻译回信封；连程序员自己都没预料到的异常也有兜底：记录服务端日志，但对前端只回一句"系统繁忙"，绝不回显堆栈——防止内部路径、SQL 错误泄露给攻击者。

面试话术："我项目里所有接口走统一信封 {code,message,data}，业务异常和系统异常分流：可预期的业务失败带业务码返回，未知异常全局兜底 500 且只记日志不外泄——这是安全和体验的双重考虑。"

530 秒面试版（背下来）

"请求先进拦截器做鉴权——我们用黑白名单控制哪些路径要登录，还排除了支付回调因为它靠验签而不是 Cookie；身份放 ThreadLocal 且请求结束必须清理，因为 Tomcat 线程复用会串号。然后到 Controller，它很薄，只做参数翻译。业务规矩全在 Service，取数在 Mapper（MyBatis-Plus）。返回时统一包成 {code,message,data} 信封，异常由全局处理器兜底，未知错误只记日志不外泄。"

自检测验

先在心里作答，再点开答案。答错不丢人——答错的地方正是下一课要加固的。

1. 如果 AuthInterceptor 删掉 afterCompletion 里的 clear()，会发生什么？

  • A · 线程被复用，下个请求可能读到上个用户身份
  • B · 内存持续增长，最终触发一次 Full GC 停顿
  • C · 事务边界被打乱，订单数据产生脏写风险
  • D · 拦截器执行链中断，Admin 角色校验被跳过
查看答案与解析

A。ThreadLocal 绑定的是线程而不是请求；Tomcat 线程池复用线程，请求结束不清理，下一个请求拿到同一线程时就能读到上一个用户的身份。这就是代码里"红线"注释的原因（AuthInterceptor.java:15）。B/C/D 都不是 ThreadLocal 不清理的直接后果。

2. 支付回调 /mall/payments/fake/notify 为什么被排除在鉴权拦截器之外？

  • A · 调用方是支付网关，手里没有用户的登录 Cookie
  • B · 该端点只读不写数据库，即使泄露也无风险
  • C · 回调请求频率太高，过拦截器会影响吞吐性能
  • D · 网关层的 IP 白名单已经完成身份核验工作
查看答案与解析

A。注释写得很直白（WebMvcConfig.java:35-36）："网关调用/浏览器直开，无用户 Cookie，鉴权靠验签"。它是"服务器对服务器"的调用，身份的证明方式是数字签名（md5 验签），不是用户的登录态。B 错误——它恰恰要写库（改订单状态）。

3. BusinessException 和普通 RuntimeException 在本项目中的分工是什么？

  • A · 预期业务失败带码返回，系统异常统一兜底五百
  • B · 前者命中缓存快速返回，后者回源数据库查询
  • C · 前者只写错误日志，后者才向前端返回提示
  • D · 前者由前端直接处理，后者由后台异步处理掉
查看答案与解析

A。BusinessException 的类注释（common/BusinessException.java:6-7）写明：仅用于"可预期的业务失败"（如商品不存在），由全局异常处理器翻译成带业务码的信封；系统异常直接抛 RuntimeException，走 500 兜底分支（GlobalExceptionHandler.java:56-60），记日志但不外泄。
