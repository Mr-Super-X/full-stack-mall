Compose 运维速查表

用于 full-stack-mall 的本地学习与一次性测试环境。先确认所在目录和操作影响，再执行命令。

返回第 9 课 学习工作区 学习路线
红线：docker compose down -v 会删除 Compose 声明的命名卷，不是普通重启。真实服务器、含重要数据的本地环境、停止写入、数据库恢复和回滚，不因出现在本速查表中就获得执行授权。

1 · 根目录：全栈容器

工作目录：仓库根目录。公开入口：http://localhost:8080。

目的命令影响与观察点
只查看服务名docker compose config --services不启动容器，不展开完整敏感配置
构建并启动docker compose up -d --build代码更新后使用；首次构建可能较慢
查看状态docker compose ps同时看进程状态和健康状态，不只看 Up
跟踪单个服务日志docker compose logs -f backend服务名也可为 web、mysql、mall-redis、mall-rabbit
停止单个服务docker compose stop backend保留容器、网络和卷，用于观察依赖故障
启动已有服务docker compose start backend不重新构建镜像；启动后仍需健康与业务验证
重启单个服务docker compose restart backend不重新构建，不等于加载新代码
停止整套服务docker compose stop保留容器，之后可用 start 恢复
删除容器和网络docker compose downCompose 声明的命名卷默认保留
永久重置数据docker compose down -v删除命名卷；仅限明确授权的一次性数据

2 · 本地开发：基础设施容器 + 本机 Maven

工作目录与根编排不同。MySQL 使用宿主机 13306，后端监听 18080，context path 为 /api。

cd backend
docker compose up -d
mvn spring-boot:run
  • 这里的 Spring Boot 在本机运行，不在 backend 容器内。
  • 运行后端测试使用 mvn test；课程材料不代替真实执行结果。
  • 改 backend/sql/init.sql 不会自动更新已有数据库，不能据此直接删除重要数据卷。

3 · 业务链路验证

# 全栈容器入口
curl -f http://localhost:8080/api/mall/product/list

# 后端容器内部检查（根编排未公开后端宿主机端口）
docker compose exec backend wget -qO- http://127.0.0.1:18080/api/mall/product/list
观察能说明什么不能说明什么
Nginx 健康检查通过对应 Nginx 检查可用后端和所有业务链路都正常
商品接口返回 JSON该请求经过的路径和依赖基本可用支付、MQ、结算和全部鉴权场景均正确
容器显示 Up容器主进程当前运行应用已就绪或业务请求成功
健康检查为 healthy所配置的检查命令通过检查未覆盖的功能都正确

4 · 排障顺序：一次只走一段

顺序检查常用证据
1浏览器实际请求的 URL、方法、状态码开发者工具 Network，不凭页面文案猜
2Nginx 是否运行、是否收到请求docker compose ps、logs web
3后端容器／本机进程是否健康logs backend、健康状态、容器内 wget
4请求是否被鉴权或 CORS 拒绝HTTP 状态、响应头、后端配置与日志
5Controller／Service 是否进入真实日志和接口响应，不无依据加 try/catch
6MySQL／Redis／RabbitMQ 是否可用各服务状态、日志、连接配置

先确定失败发生在哪一段，再修改对应配置。不要同时改端口、CORS、Nginx、鉴权和数据库，也不要用删除数据卷制造“看起来恢复”。

5 · 独立部署入口

以下只标明入口，详细前置条件、验证与联动要求必须阅读对应文档。

# 后端：先配置未入库的 .env，再启动
cd deploy/backend
bash deploy.sh start
bash deploy.sh status
bash deploy.sh logs backend

# 前端：后端已运行后，在另一目录启动
cd ../frontend
bash deploy.sh start
bash deploy.sh status
  • 独立部署默认入口为 http://10.2.161.161:9088/，实际使用前先确认目标环境和地址。
  • 后端容器重建后，按 deploy/backend/README.md 重启前端，让 Nginx 重新解析 upstream；普通后端 restart 不等同于重建。
  • 真实 .env、备份和业务数据不得粘贴到课堂反馈或提交到 Git。

6 · 备份、恢复与回滚：证据边界

动作入口必须补的验证
MySQL 备份deploy/backend/README.md 第 4 节gzip 校验只是文件完整性；可恢复性要在一次性测试库演练
MySQL 恢复同文档第 5 节会覆盖同名表数据；先备份当前库、停止写入并确认目标
前端备份deploy/frontend/README.md 第 5 节确认镜像标签与实际运行镜像对应，保存整个备份目录
前端回滚同文档第 6 节不能用会按当前源码重建的 start，也不能只用普通 restart

MySQL SQL 备份不包含 Redis 与 RabbitMQ 的全部运行状态。使用 Redis 秒杀策略时，必须先阅读文档中的停写与队列消费要求，不能声称一份 SQL 就恢复整个系统。
