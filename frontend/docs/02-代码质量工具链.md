# 代码质量工具链配置详解

> **文档版本**：v1.0.0 | **最后更新**：2026-07-20
> **覆盖工具**：ESLint 10 + Prettier 3.9 + lint-staged 17

---

## 📋 工具一览

| 工具              | 版本    | 作用                                 | 触发时机                  |
| ----------------- | ------- | ------------------------------------ | ------------------------- |
| **ESLint**        | ^10.7.0 | TypeScript + Vue 代码静态检查        | pre-commit（lint-staged） |
| **Prettier**      | ^3.9.5  | 代码格式化（去分号、单引号、尾逗号） | pre-commit（lint-staged） |
| **lint-staged**   | ^17.0.8 | 仅对 Git 暂存区文件运行 lint/format  | pre-commit 钩子           |
| **.editorconfig** | -       | 统一编辑器配置（缩进/换行/编码）     | 打开文件时 IDE 自动应用   |

---

## 🔄 工作流

```
git commit
   ↓
[husky pre-commit 触发]（Monorepo 迁移期精简版，实跑 2 步）
   ↓
pnpm lint-staged
   ├── 对暂存的 *.ts / *.vue → eslint --fix + prettier --write
   ├── 对暂存的 *.json / *.md / *.scss 等 → prettier --write
   └── 自动 stage 修复后的变更
   ↓
pnpm check:routes（路由一致性：RouteName + whitelist + 实际 routes）
   ↓
✅ 通过 → commit 完成（commit-msg 钩子随后校验 message，见 docs/03）
```

> type-check 不在本地 pre-commit（秒级提交体验优先），由 CI 的 turbo build（内含
> type-check:full）统一拦截。

## ⚙️ 配置文件

### `eslint.config.mjs`（ESLint 10 flat config）

```js
import pluginVue from 'eslint-plugin-vue'
// v14.9+ 推荐 API：withVueTs（替代旧的 vueTsEslintConfig()——旧 API 声明 scriptLangs
// 要靠 configureVueProject 改全局状态，而 demo 的 JSX 插槽示例需要 <script setup lang="tsx">）
import { withVueTs, vueTsConfigs } from '@vue/eslint-config-typescript'
import skipFormatting from '@vue/eslint-config-prettier/skip-formatting'

// 单一职责：组合 Vue/TS/Prettier 三层规则
// Prettier 规则必须放最后，避免与 Prettier 冲突
export default withVueTs(
  // scriptLangs 默认 ['ts']，显式加 'tsx' 才允许 .vue 内写 JSX
  { scriptLangs: ['ts', 'tsx'] },
  {
    name: 'app/files-to-lint',
    files: ['**/*.{ts,mts,tsx,vue}'],
  },
  {
    name: 'app/files-to-ignore',
    ignores: ['**/dist/**', '**/coverage/**', '**/node_modules/**', '**/.husky/**', '**/mock/**'],
  },
  ...pluginVue.configs['flat/essential'],
  // TypeScript 规则等级（vueTsConfigs.recommended ≈ 旧 vueTsEslintConfig() 默认）
  vueTsConfigs.recommended,
  // 项目级规则覆盖：
  // - 关闭单字组件名（项目刻意保持简洁命名）
  // - 允许 _ 前缀变量被忽略（用于"解构但暂不使用"的场景）
  {
    rules: {
      'vue/multi-word-component-names': 'off',
      '@typescript-eslint/no-unused-vars': [
        'error',
        { argsIgnorePattern: '^_', varsIgnorePattern: '^_' },
      ],
    },
  },
  skipFormatting
)
```

> 完整配置（含业务目录 `no-restricted-imports` 拦截 useRouter/axios 等）见 `eslint.config.mjs` 源文件。

**设计要点**：

- **flat config 格式**（ESLint 9+ 官方格式，`.eslintrc.cjs` 已废弃）
- **三层规则组合**：Vue 官方 essential + Vue-TS + Prettier 跳过
- **项目级覆盖**：单字组件名关闭 + `_` 前缀忽略

### `.prettierrc.json`（Prettier 3.9）

```json
{
  "printWidth": 100,
  "tabWidth": 2,
  "useTabs": false,
  "semi": false,
  "singleQuote": true,
  "jsxSingleQuote": false,
  "trailingComma": "es5",
  "bracketSpacing": true,
  "bracketSameLine": false,
  "quoteProps": "as-needed",
  "vueIndentScriptAndStyle": false,
  "embeddedLanguageFormatting": "auto",
  "htmlWhitespaceSensitivity": "ignore",
  "arrowParens": "always",
  "endOfLine": "lf",
  "singleAttributePerLine": false
}
```

**风格选择理由**（基于 Vue 3 / Vite / Next.js 社区主流惯例）：

| 配置                         | 值            | 原因                                                                                        |
| ---------------------------- | ------------- | ------------------------------------------------------------------------------------------- |
| `printWidth`                 | `100`         | Vue / Vite 主流（不是 80 也不是 120）                                                       |
| `tabWidth`                   | `2`           | 2 空格缩进（项目标准）                                                                      |
| `useTabs`                    | `false`       | 不用 tab 用空格（跨平台一致性）                                                             |
| `semi`                       | `false`       | 无分号（Vue 生态主流）                                                                      |
| `singleQuote`                | `true`        | 单引号（与 ESLint @stylistic 一致）                                                         |
| `jsxSingleQuote`             | `false`       | JSX 仍用双引号（React 兼容）                                                                |
| `trailingComma`              | `"es5"`       | 兼容 ES5 的位置加尾逗号（比 `all` 严，比 `none` 松）                                        |
| `bracketSpacing`             | `true`        | 对象字面量 `{ foo: bar }` 加空格（默认）                                                    |
| `bracketSameLine`            | `false`       | 多行 JSX 元素的 `>` 放下一行（默认；Prettier 3.0+ 新名，替代已弃用的 `jsxBracketSameLine`） |
| `quoteProps`                 | `"as-needed"` | 只在必须时给对象 key 加引号（默认）                                                         |
| `vueIndentScriptAndStyle`    | `false`       | Vue 的 `<script>` 和 `<style>` 不缩进（默认行为）                                           |
| `embeddedLanguageFormatting` | `"auto"`      | 允许自动格式化内嵌代码块（默认）                                                            |
| `htmlWhitespaceSensitivity`  | `"ignore"`    | Vue 模板友好（HTML 标签尾空格不敏感）                                                       |
| `arrowParens`                | `"always"`    | 箭头函数总是加括号（Prettier 3.0 默认，主流）                                               |
| `endOfLine`                  | `"lf"`        | LF 换行符（跨平台一致性，Vue 主流）                                                         |
| `singleAttributePerLine`     | `false`       | HTML/Vue/JSX 不强制单属性一行（默认）                                                       |

**为什么不包含 `disableLanguages` / `eslintIntegration` / `stylelintIntegration` / `requireConfig` / `ignorePath`**：

- 这些是 **Prettier 2.x 时代的字段**，Prettier 3.0 已删除
- 加载时会输出 `Ignored unknown option` 警告
- 官方推荐：只保留 Prettier 3.x 实际支持的字段（**16 个**，覆盖所有有效配置）

### `.lintstagedrc.json`（lint-staged 17，独立配置文件）

```json
{
  "*.{ts,vue}": ["eslint --fix --no-warn-ignored", "prettier --write"],
  "*.{json,md,scss,css,yml,yaml}": ["prettier --write"]
}
```

> **为什么独立文件**：`package.json` 的 `lint-staged` 字段会让 npm 10/11 在依赖解析阶段崩溃（arborist 把未知字段当作依赖列表）。移到独立文件避免冲突。

### `.husky/pre-commit`

```sh
# Monorepo 迁移期临时精简钩子（2026-10-21，P0 阶段启用）
# 原五步链（generate:tsconfig-paths / type-check / check:aliases）假设单根 src/，
# P0-P1 迁移期结构性不适用；完整多包门禁链在 P5 重建：
# docs/superpowers/plans/2026-10-21-monorepo-migration.md（Task P5-1 / P5-5）
# 暂存区文件先自动格式化 + ESLint fix（lint-staged 仅处理变更文件，不全库扫描）
pnpm lint-staged
# 路由一致性检查（P0-2 起已改指 apps/*/src/modules，P0 期间仍指 src/，均可用）

```

> ⚠ type-check / check:aliases 不在本地 pre-commit（秒级提交体验优先），由 ci.yml 兜底。

### `.editorconfig`（Vue 官方最佳实践）

> **作用**：统一 IDE 编辑器行为（缩进、换行符、编码、文件末尾空行）。与 ESLint/Prettier 互补，作用于"打开文件时"，Prettier 作用于"保存时"。

```ini
root = true

[*]
indent_style = space
indent_size = 2
end_of_line = lf
charset = utf-8
trim_trailing_whitespace = true
insert_final_newline = true

[*.md]
trim_trailing_whitespace = false

[*.{yml,yaml}]
indent_size = 2
```

**各项配置说明**：

| 配置                       | 值      | 作用                                  | 适用                    |
| -------------------------- | ------- | ------------------------------------- | ----------------------- |
| `root`                     | `true`  | 停止向上查找其他 .editorconfig        | 项目根目录              |
| `indent_style`             | `space` | 用空格缩进（不用 tab）                | 全部文件                |
| `indent_size`              | `2`     | 2 空格缩进                            | 全部文件                |
| `end_of_line`              | `lf`    | LF 换行符（跨平台一致）               | 全部文件                |
| `charset`                  | `utf-8` | 统一编码                              | 全部文件                |
| `trim_trailing_whitespace` | `true`  | 删行尾空格                            | 全部文件（除 markdown） |
| `insert_final_newline`     | `true`  | 文件末尾插入空行                      | 全部文件                |
| `[*.md]` 例外              | -       | 保留 markdown 行尾空格（用于换行）    | `.md`                   |
| `[*.{yml,yaml}]` 显式      | -       | 显式声明 2 空格（防止某些工具默认 4） | `.yml` `.yaml`          |

**为什么 `[*.md]` 例外**：

Markdown 用行尾 2 个空格表示"强制换行"（`<br>`）：

```
第一行末尾加两个空格
第二行
```

如果 `trim_trailing_whitespace = true` 强制删所有行尾空格，会破坏 markdown 换行语法。

**与 Prettier 的协同关系**：

| 阶段     | 工具                              | 触发时机                      |
| -------- | --------------------------------- | ----------------------------- |
| 打开文件 | `.editorconfig`                   | IDE 加载文件时（自动）        |
| 保存文件 | `Prettier`                        | 手动保存或 hook 触发          |
| 提交代码 | `lint-staged` → Prettier + ESLint | `git commit` / `pnpm push` 时 |

**一致项**：`indent_size: 2` + `end_of_line: lf` 与 Prettier 配置保持一致。
**唯一冲突点**：markdown 行尾空格——`.editorconfig` 保留，`Prettier` 配置 `"htmlWhitespaceSensitivity": "ignore"` 也保留（双保险）。

## 🐛 故障排查

### 1. `eslint.config.js` 被 Write 工具拦截

**症状**：`BLOCKED: Modifying eslint.config.js is not allowed`

**原因**：全局 `config-protection` hook 保护常见配置文件名

**解决**：用 `eslint.config.mjs`（hook 不匹配这个文件名）

### 2. 单字组件名被 `vue/multi-word-component-names` 报错

**症状**：`Component name "Header" should always be multi-word`

**解决**：已在 `.eslint.config.mjs` 关闭此规则（项目刻意保留 Header/Sidebar/Login 等简洁命名）

### 3. 暂存区文件 ESLint 检查时报 `Cannot find module 'element-plus'`

**症状**：`lint-staged` 跑 `eslint --fix` 报模块找不到

**解决**：vitest 配置已收敛为工厂单源——`packages/config/src/create-vitest-config.ts` 的
`createVitestConfig({ appRoot, viteConfig, coverage })` + `apps/admin/vitest.config.ts` 参数注入；
`server.deps.inline` / `css` 等参数在工厂内统一处理，各 app 只传 appRoot 与 coverage 覆盖。

### 4. `pnpm format` 一次改了几十个文件

**症状**：运行 `pnpm format` 后 60+ 文件变更

**解决**：这是首次格式化项目的预期行为。提交前 review 一次即可

### 5. `pnpm dev` 报 CSS 处理错误

**症状**：`TypeError: Unknown file extension ".css"`

**解决**：`css: true` 由 `packages/config/src/create-vitest-config.ts` 工厂统一启用（同上 #3）

## 📌 项目自定义 ESLint 规则（DS-4/DS-7 补齐）

> `eslint.config.mjs` 已通过 `no-restricted-imports` 强制业务代码走项目封装（替代"靠 code review 把关"）。本节列出当前已配置的规则及其与 `CLAUDE.md §1.5` 的对应关系。

### 当前规则

| 规则                                                   | 来源         | 触发条件                                 | 级别   | 替代封装                                 |
| ------------------------------------------------------ | ------------ | ---------------------------------------- | ------ | ---------------------------------------- |
| `vue-router/useRouter`（`importNames: ['useRouter']`） | `vue-router` | `import { useRouter } from 'vue-router'` | `warn` | `@composables/useAppRouter`              |
| `axios` / `axios/*`                                    | `axios`      | `import axios from 'axios'`              | `warn` | `@composables/useRequest` / `@api/_http` |

### Monorepo 边界规则（v3.0.0 P5-A 落地，error 级）

CLAUDE.md §2.1 依赖方向铁律的机械强制手段，全部 `error` 级（`pnpm lint` / CI 直接阻断）：

| 规则                                      | 作用域                                | 拦截内容                                                                    |
| ----------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------- |
| `app/business-wrap-rule`                  | `apps/*/src/**`                       | 业务代码裸用 vue-router `useRouter` / axios（warn，与上表同源）             |
| `app/boundary-packages`                   | `packages/**/*`                       | 包引用 apps/** 或 app 私有别名（@modules/@layouts/@router/@plugins）        |
| `local/package-contract`                  | `packages/**` + `apps/**`             | 依赖未在本 package.json 声明 + @vv/* 方向铁律（mock → shared、ui → shared） |
| `app/ui-subsystem-boundary`               | `packages/ui` 的 form-schema/ProTable | 两子系统双向禁 import（保持编译期零互依）                                   |
| `app/boundary-apps-<a>`（6 app 动态生成） | `apps/<a>/src/**`                     | 相对逃逸/绝对路径引用其他 5 个 app（跨 app 通信走整页跳转协议）             |

### 与 CLAUDE.md §1.5 必用 composable 的对照

| CLAUDE.md §1.5 强制封装   | ESLint 规则覆盖         | 缺口处理                                                                  |
| ------------------------- | ----------------------- | ------------------------------------------------------------------------- |
| `useAppRouter`（路由）    | ✅ vue-router/useRouter | —                                                                         |
| `useRequest`（网络请求）  | ✅ axios                | —                                                                         |
| `useAuth`（权限）         | ❌ 无                   | 由 `useAuth` composable 显式 import 把关；code review 兜底                |
| `useDialog`（命令式弹窗） | ❌ 无                   | `pinia` 类的设计已成熟，业务通常直接用 `useDialog(...)`；code review 把关 |
| `useConfirm`（二次确认）  | ❌ 无                   | 同上                                                                      |

### 为什么不全量加规则

1. **误报风险高**：`useAuth` / `useDialog` / `useConfirm` 本身也通过 import 引入，单纯限制 `pinia` importNames 不能区分「业务读 store」vs「封装内读 store」
2. **重构成本**：3 条新规则需要为 composable 内部 import 全部加 inline disable comments，影响可读性
3. **CLAUDE.md §1.5 措辞**：原文是「`ESLint no-restricted-imports 自动 warning`」——**实际只覆盖了 2 条**，其他 3 条靠规范 + code review。把"自动 warning"改为"规则 + 规范"更准确（DS-8 修正）

### 后续扩展（如需）

如要补齐 3 条规则，建议方案：

```js
// eslint.config.mjs 草稿（未启用，仅供参考；路径为 Monorepo 口径——
// user store 已迁 @vv/shared 包，@store 别名指向 packages/shared/src/store）
{
  group: ['@store/modules/user', '@store/modules/auth'],
  importNames: ['useUserStore', 'useAuthStore'],
  message: '业务代码请通过 @composables/useAuth 包装',
},
```

**警告**：启用前需全局排查 `src/modules/*/views` 中直接 useUserStore 的调用点（项目内已知至少 5+ 处），逐个迁移到 `useAuth()` 后再启用规则。**不在本轮同步范围**。
