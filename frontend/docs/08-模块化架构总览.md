# 模块化架构总览

> 涵盖项目 src/ 下**所有可复用模块**（directives / plugins / components / utils / store / router）的设计原则、目录结构、统一范式与扩展流程。
> 与各模块配套的详细规范（路由、主题、BEM、构建工具等）见 docs/01-07。

---

## 1. 设计原则

| 原则         | 说明                                                           |
| ------------ | -------------------------------------------------------------- |
| **单一职责** | 每个模块只做一件事（如 directives 只管自定义指令）             |
| **范式一致** | 同一类模块用同一套约定（如所有 directives 都 install 模式）    |
| **类型优先** | TypeScript strict + exactOptionalPropertyTypes 严格模式        |
| **单一来源** | 同类配置只在一处维护（如 alias 系统在 vite + tsconfig 双映射） |
| **可扩展**   | 预留扩展点（plugins.errorHandler.report 让用户接 Sentry）      |

---

## 2. 目录结构（Monorepo workspace）

> v3.0.0 起单应用 `src/` 升级为 pnpm workspace + turbo Monorepo：全局可复用层归 `packages/*`，各 app 持有私有 `apps/<a>/src/`。完整拓扑、依赖方向铁律与 6 app 清单见 `docs/43-Monorepo结构与开发指引.md`。

```
packages/shared/src/   # 全局层：api/ composables/ directives/ enums/ locales/ store/（4 全局 store barrel）utils/ router/ router-guards/ plugins/ auth/
packages/ui/src/       # 全局组件三目录（components/common + ProTable + form-schema，unplugin 自动注册）+ assets/styles/ + composables/（弹窗族 useDialog/useConfirm/useLogout）
packages/mock/src/     # @vv/mock：vite-plugin-mock 数据源
packages/config/src/   # @vv/config：vite 工厂（createViteConfig）+ app-aliases.ts 别名单源
apps/<a>/src/          # app 私有：modules/（业务模块自包含）layouts/ router/ store/（私有 store 出口）views/ plugins/ types/ ...
```

**核心原则**：

- **每个子目录有独立边界**——可独立测试、独立维护
- **范式一致**——所有子目录的注册入口都是 `export default { install(app) {...} }`（如果有 install 行为）
- **依赖方向铁律**：`apps/* → packages/*` 单向；包间 config ∥ shared → mock → ui（详见 docs/43）
- 各 app 内部 `src/` 一级目录沿用单应用时期 Lockdown（api/assets/components/... 不得增删改，见 CLAUDE.md §2）
- **store 口径**：全局 barrel 只有 4 个（app / user / theme / dict，@vv/shared）；tags-view 与 router 是 admin 私有（apps/admin/src/store/）——详见 docs/19 §2

## 3. 4 块公共范式

项目内有 4 类"可注册模块"，每类都有统一的范式约定：

### 3.1 Directives 范式

> 位置：`packages/shared/src/directives/`（@vv/shared 包）。`index.ts` 是 **import.meta.glob 自动注册插件**——新增指令只需丢 `v-xxx.ts` 文件进目录，无须改 index.ts、无须动 main.ts（glob 自动跳过 `index.ts` / `_` 前缀内部工具 / `.d.ts` / `.spec.ts`）。

```ts
// xxx.d.ts — 类型定义
export type ElHTMLElement = HTMLElement
export interface XxxBinding { value: ...; arg?: string }

// xxx.ts — install 模式实现（glob 扫描 default export { install } 自动注册）
import type { App } from 'vue'
import { isFunction } from './_utils'
import type { ElHTMLElement, XxxBinding } from './xxx.d'

export default {
  install(app: App) {
    app.directive<ElHTMLElement, XxxBinding['value']>('xxx', {
      mounted(el, binding) { ... }
    })
  }
}

// index.ts — 统一注册入口（glob 自动注册，非手写 import 链）
const modules = import.meta.glob<DirectiveModule>(['./*.ts', '!./**/*.spec.ts', '!./**/*.d.ts'], { eager: true })
const install = (app: App) => {
  autoImport({ modules, filter: 跳过 index/_ 前缀, transform: 调 plugin.install(app) })
}
export default install
```

**约定**：

- 每个指令独立 `.d.ts` 类型文件
- install 模式导出（glob 靠 `default.export.install` 识别注册）
- 通用工具放 `_utils.ts`（前缀下划线，glob 跳过）
- index.ts 是 glob 自动注册插件，**不要**回退成手写 `import xxx from './xxx'` 链

### 3.2 Plugins 范式

与 Directives 同形（install 模式 + .d.ts 分离）。差异在注册入口：@vv/shared 的插件统一走 **`createAppPlugins` 工厂**（`packages/shared/src/plugins/index.ts`，P6 下沉——原 5 app plugins/index.ts 同构拷贝收敛）；各 app `plugins/index.ts` 退化为一行薄封装 `export default createAppPlugins({ remAdaptation: true })`（仅 admin / h5 传 remAdaptation）。

```ts
// packages/shared/src/plugins/xxx.d.ts
export interface XxxOptions { ... }
export interface PluginsOptions { xxx?: XxxOptions | false }

// xxx.ts — install 模式实现
import type { App } from 'vue'
import type { XxxOptions } from './xxx.d'

export default {
  install(app: App, options: XxxOptions = {}) { ... }
}

// createAppPlugins 工厂装配序（errorHandler → webVitals → [remAdaptation] → versionCheck；
// 各项默认启用，app.use(Plugins, { xxx: false }) 可单独关闭）
```

> app 私有插件（不进 @vv/shared 的）仍适用手写 install + index.ts 装配范式，范围限于 `apps/<a>/src/plugins/`。

### 3.3 Components 自动注册范式

> Monorepo 后**不存在 `src/components/index.ts` 手写注册插件**——全局组件由 `packages/config/src/create-vite-config.ts` 的 `unplugin-vue-components` Components 段按 `dirs` 自动扫描注册（CLAUDE.md §1.7 强约束）。

```ts
// packages/config/src/create-vite-config.ts Components 段（节选）
Components({
  resolvers: [
    ElementPlusResolver({ importStyle: 'css' }), // 第三方组件库按需注入
    IconsResolver({
      prefix: 'i',
      enabledCollections: ['ep', 'tabler'],
      customCollections: ['app'],
    }),
  ],
  // 扫描目录：@vv/ui 三目录 + appRoot/src/components（existsSync 过滤，作未来 app 私有组件扩展位）
  dirs: [
    path.join(UI_SRC_DIR, 'components/common'),
    path.join(UI_SRC_DIR, 'components/ProTable'),
    path.join(UI_SRC_DIR, 'components/form-schema'),
    path.join(appRoot, 'src/components'),
  ].filter((dir) => existsSync(dir)),
  deep: true, // 深层子目录全部自动注册
  dts: path.join(appRoot, 'src/types/components.d.ts'), // dev/build 时生成，.gitignore 屏蔽
})
```

**约定**（与 CLAUDE.md §1.7 对齐）：

- 扫描范围：`@vv/ui` 包源码三目录（`components/common/` + `components/ProTable/` + `components/form-schema/`）+ 各 app 的 `src/components/`（若存在），`deep: true` 含任意深度子目录
- 模板中直接 `<BaseChart />` / `<ProTable />` / `<XForm />`，**不要显式 import**——IDE 经 `vue.GlobalComponents`（components.d.ts）展示完整 `DefineComponent<Props, Expose, ...>` 类型签名
- 旧版"import.meta.glob + `_`/`.` 跳过 + index.ts 插件"范式已退役（glob 自动注册仅保留在 directives/plugins 两类）

### 3.4 Utils 范式

```ts
// xxx.ts — 纯函数工具
export function xxxFn(input: Input): Output { ... }

// xxx.spec.ts — Vitest 单测
import { describe, it, expect } from 'vitest'
describe('xxxFn', () => {
  it('case', () => { expect(xxxFn(input)).toBe(expected) })
})
```

**约定**：

- 纯函数（无副作用）+ 完整类型签名
- 每个工具函数配 Vitest 单测
- 不依赖 Vue（与框架解耦）

## 4. Directives 模块详解

> 位置：`packages/shared/src/directives/`（@vv/shared 包）。6 个指令 + `_utils.ts` 共享工具 + `index.ts`（import.meta.glob 自动注册插件，见 §3.1）。

### 当前指令清单

| 指令               | 用法                                                                            | 行为                                                                                                |
| ------------------ | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `v-inputDebounce`  | `v-inputDebounce:300="onInput"`                                                 | input 事件 trailing edge 防抖（默认 300ms）                                                         |
| `v-buttonDebounce` | `v-buttonDebounce:500="onClick"`                                                | click 事件 trailing edge 防抖（默认 500ms）                                                         |
| `v-permission`     | `v-permission="['user:edit']"`                                                  | 整页 / 整块 DOM 权限占位                                                                            |
| `v-auth`           | `v-auth="['user:create']"` 或 `v-auth:any.remove="['user:edit','user:delete']"` | 按钮级权限（AND / ANY 语义 + `disabled`/`remove` 修饰符），详见 `docs/23-权限设计.md`               |
| `v-draggable`      | `v-draggable="enabled"`                                                         | DOM 拖拽指令（钳制在视口边界内），被 `<ProDialog>` 默认消费，详见 `docs/27-ProDialog使用指南.md` §4 |
| `v-copy`           | `v-copy="'text'"` 或 `v-copy="() => \`动态值\`"`                                | 文本复制（modern API + legacy 双降级；详见 [`docs/32-常用交互指令.md`](32-常用交互指令.md) §1）     |

### 共享工具（`_utils.ts`）

```ts
type EventHandler = (this: HTMLElement, event: Event) => void

export function debounce(click: EventHandler, timeout: number): EventHandler { ... }
export function isFunction(param: unknown): param is (...args: unknown[]) => unknown { ... }
```

### 扩展：新指令的标准流程

1. 创建 `xxx.d.ts` 定义 `ElHTMLElement` + `XxxBinding`
2. 创建 `xxx.ts` 用 `export default { install(app) {...} }` 模式
3. **无需改 `index.ts`**——glob 自动扫描注册（跳过 `_` 前缀 / `.d.ts` / `.spec.ts` / index 自身）
4. （如需共用工具）扩 `_utils.ts`
5. CHANGELOG +1 条目 + commit

## 5. Plugins 模块详解

> 位置：`packages/shared/src/plugins/`（@vv/shared 包），经 `createAppPlugins` 工厂统一装配（§3.2）。

### 当前插件

| 插件            | 职责         | 关键能力                                                                                               |
| --------------- | ------------ | ------------------------------------------------------------------------------------------------------ |
| `errorHandler`  | 全局错误兜底 | 接管 Vue 错误 / window 错误 / Promise 拒绝；预留 `report` 回调接 Sentry                                |
| `webVitals`     | 性能指标采集 | Web Vitals 指标采集（dev console 徽章 / prod 默认 noop），`options.webVitals.report` 自定义上报        |
| `remAdaptation` | REM 适配     | viewport meta 幂等确保（仅 admin / h5 经工厂参数装配；fontSize 激活归 apps/h5 的 layouts/h5 生命周期） |
| `versionCheck`  | 版本检测     | 轮询 version.json 比对 buildId + ChunkLoadError 兜底（dev 默认不启动）                                 |

### errorHandler 用法

```ts
// main.ts
import Plugins from '@plugins'

app.use(Plugins, {
  errorHandler: {
    // 生产环境对接 Sentry/自建日志
    report: (error, ctx) => {
      Sentry.captureException(error, { tags: { source: ctx.source } })
    },
    // dev 默认 true / prod 默认 false
    logToConsole: import.meta.env.DEV,
  },
})

// 完全关闭（罕见）
app.use(Plugins, { errorHandler: false })
```

### errorHandler 事件来源

| 来源                   | 含义                                                     |
| ---------------------- | -------------------------------------------------------- |
| `'vue'`                | Vue 组件渲染 / 生命周期抛错（`app.config.errorHandler`） |
| `'window.error'`       | window 全局 JS 错误（语法错误、未捕获异常）              |
| `'unhandledrejection'` | 未捕获的 Promise 拒绝                                    |

### 扩展：新插件的标准流程

1. 创建 `xxx.d.ts` 定义 options + 类型
2. 创建 `xxx.ts` 用 `export default { install(app, options) {...} }` 模式
3. `errorHandler.d.ts` 的 `PluginsOptions` 加 `xxx?: XxxOptions | false` 字段 + `createAppPlugins` 工厂 install 内加对应 `app.use` 装配行（支持 `false` 关闭）
4. CHANGELOG +1 条目 + commit

### 未来扩展点

| 插件               | 触发条件                                       |
| ------------------ | ---------------------------------------------- |
| `analyticsPlugin`  | 接入 GA / 百度统计 / 神策                      |
| `sentryPlugin`     | 生产环境错误监控（可替代 errorHandler.report） |
| `permissionPlugin` | 与 directives 配合做细粒度权限                 |

## 6. Alias 系统

> **架构基线更新**：2026-09-10 起 alias 配置抽离为**单一来源**（commit `8b7178c`）；v3.0.0 Monorepo 迁移后单一来源为 `packages/config/src/app-aliases.ts` 的 `createAppAliases()`，由 `scripts/generate-tsconfig-paths.ts` 自动同步到各 app 的 `tsconfig.app.json`，**消除原先 vite.config.ts 与 tsconfig.app.json 的双维护痛点**。详见 §6.1。

### 6.1 单一来源 + 自动同步

| 角色          | 文件                                                         | 职责                                                                                         |
| ------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| **单一来源**  | `packages/config/src/app-aliases.ts`（`createAppAliases()`） | vite 侧 + tsconfig 侧的 alias 唯一真相，17 个键（1 个 `@` + 14 个具名 + 2 个包名裸路径兜底） |
| vite 消费     | `packages/config/src/create-vite-config.ts` 的 resolve.alias | 各 app `vite.config.ts` 调 `createViteConfig()` 时由工厂统一注入 alias                       |
| tsconfig 消费 | `scripts/generate-tsconfig-paths.ts`                         | 读 `createAppAliases` → 自动写入各 app `tsconfig.app.json` 的 `paths`                        |
| 校验门        | `pnpm check:aliases`                                         | 对比 `createAppAliases` 与各 app `tsconfig.app.json` 的 `paths`，漂移则 CI 失败              |
| 钩子保障      | `.husky/pre-commit`                                          | `lint-staged` + `pnpm check:routes`（Monorepo 迁移期精简版，秒级不卡提交）                   |

### 6.2 当前 Alias 一览（17 个：1 个根 alias + 14 个具名子 alias + 2 个包名裸路径兜底）

```ts
// packages/config/src/app-aliases.ts —— createAppAliases(appRoot) 返回的映射（按归属分组）
{
  // app 私有（@/ 恒指各 app 自身 src，永久保留）
  '@':        '<appRoot>/src',
  '@modules': '<appRoot>/src/modules',
  '@layouts': '<appRoot>/src/layouts',
  '@router':  '<appRoot>/src/router',
  '@plugins': '<appRoot>/src/plugins',
  // @vv/shared 包源码
  '@api':         'packages/shared/src/api',
  '@composables': 'packages/shared/src/composables',
  '@store':       'packages/shared/src/store',
  '@utils':       'packages/shared/src/utils',
  '@enums':       'packages/shared/src/enums',
  '@locales':     'packages/shared/src/locales',
  '@directives':  'packages/shared/src/directives',
  // @vv/ui 包源码
  '@components':  'packages/ui/src/components',
  '@assets':      'packages/ui/src/assets',
  // @vv/mock 包源码
  '@mock':        'packages/mock/src',
  // 包名裸路径兜底（2026-10-27 补录）：vue-tsc --build 对 workspace 链接的 exports 深路径
  // （'@vv/shared/api/error-events' 等）解析失败——vite/vitest 走 exports 正常，仅 TS 需 paths 兜底
  '@vv/shared':   'packages/shared/src',
  '@vv/ui':       'packages/ui/src',
}
```

`'@'` 是根 alias（指向**各 app 自身**的 `src/`）；14 个具名 alias 分两类——app 私有 4 个（`@modules` / `@layouts` / `@router` / `@plugins`）+ 包别名 10 个（指向 `packages/*` 包源码）；另有 2 个包名裸路径兜底（`@vv/shared` / `@vv/ui`）仅作 TS 侧 exports 深路径解析兜底。旧版 `@types` 条目已删除（与 TS 的 `@types` 包解析命名空间冲突，且全仓零消费——类型统一经 `@vv/shared` 包名引出）。两种用法由 tsconfig paths 同时映射（裸字符串 + 子路径），详见 §6.3。

### 6.3 为什么双映射

| 模式    | 匹配                 | 例子                                      |
| ------- | -------------------- | ----------------------------------------- |
| `XXX`   | 裸字符串（精确匹配） | `import X from '@components'`             |
| `XXX/*` | glob（任意子路径）   | `import Y from '@components/foo/Bar.vue'` |

tsconfig paths `@/*: ["./src/*"]` **不能**匹配 `@components`（裸字符串），所以每个 alias 都要写两条 paths。生成器按各 app 实际别名清单展开（当前 admin 为 26 条唯一 paths 键：裸字符串 + `/*` 子路径各一条），无需手写。

### 6.4 维护规则（v2.0 之后的流程）

**新增 app 私有子目录别名时**（如新增 `src/services/`）：

1. `packages/config/src/app-aliases.ts` 的 `createAppAliases()` 加 `'@services': path.join(appRoot, 'src/services')`（**仅一处**；包别名同理指向对应 `packages/*` 目录）
2. 跑 `pnpm generate:tsconfig-paths` 自动写入各 app `tsconfig.app.json` 的 `paths`
3. （可选）跑 `pnpm check:aliases` 验证单一来源与产物一致
4. CHANGELOG +1 条目 + commit

> **禁止**：再手动改各 app `vite.config.ts` 或 `tsconfig.app.json` 的 paths——任何手动改动都会被下一次生成器覆盖或被 `pnpm check:aliases` 阻断。

## 7. main.ts 接入范式

> Monorepo 后启动装配已单源化：@vv/shared 的 **`bootstrapApp` 工厂**（`packages/shared/src/app-mount.ts`，P6 收敛——原 6 app main.ts 逐字同构段单源，顺序契约固化在工厂内：品牌色/title → prod-mock 先于 use(router) → use 序列 → setup 收尾 → mount）。全局组件不经手写 `app.use(GlobalComponents)`——unplugin-vue-components 自动注册（§3.3）；Directives 虽仍经 `app.use` 注入，但其内部已是 glob 自动注册（§3.1）。

```ts
// apps/admin/src/main.ts — app 差异数据经参数注入工厂
import App from './App.vue'
import router from './router'
import pinia from './store'
import i18n from '@locales'
import Directives from '@directives'
import Plugins from '@plugins'
import { createGlobalComponents } from '@vv/ui'
import { setupUiAppContext } from '@vv/ui/composables/setup-ui-app-context'
import { bootstrapApp } from '@vv/shared'
import '@vv/ui/app-styles' // 样式基线四件套（normalize → uno → 全局 scss → EP dark css-vars）单源

await bootstrapApp({
  rootComponent: App,
  router,
  pinia,
  i18n,
  title: i18n.global.t('app.title'),
  globalComponents: createGlobalComponents(),
  directives: Directives,
  plugins: Plugins,
  loadMockServer: () => import('@mock/mockProdServer'),
  setup: setupUiAppContext, // 必须在所有 app.use 之后（工厂收尾段保证）
})
```

**原则**：

- app main.ts 只保留差异数据（根组件 / router / pinia / i18n / 插件 / mock 回调 / setup 收尾）
- 新增全局指令 → 丢文件进 `packages/shared/src/directives/` 即可（glob 自动注册）
- 新增 app 私有 plugin → `apps/<a>/src/plugins/` 薄封装 `createAppPlugins(...)`

## 8. 新增模块的标准流程

### 新增指令

1. 决定指令名（kebab-case），如 `v-xxx`
2. 创建 `packages/shared/src/directives/xxx.d.ts`（`ElHTMLElement` + `XxxBinding`）
3. 创建 `packages/shared/src/directives/xxx.ts`（install 模式）
4. **无需改 index.ts**——glob 自动扫描注册（§3.1）
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

### 新增插件

1. 决定插件职责（如 `analytics` / `sentry` / `permission`）
2. 创建 `packages/shared/src/plugins/xxx.d.ts`（`XxxOptions` + `PluginsOptions` 加字段）
3. 创建 `packages/shared/src/plugins/xxx.ts`（install 模式，接收 `XxxOptions`）
4. `createAppPlugins` 工厂 install 内加 `app.use` 装配行（支持 `false` 关闭；app 私有插件放 `apps/<a>/src/plugins/`）
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

### 新增 utils 工具

1. 创建 `packages/shared/src/utils/xxx.ts`（纯函数 + 完整类型）
2. 创建 `packages/shared/src/utils/xxx.spec.ts`（Vitest 单测覆盖边界）
3. 跑 `pnpm -C apps/admin test`（或对应 app）验证
4. CHANGELOG +1 + commit

### 新增全局组件

1. 创建 `packages/ui/src/components/common/Xxx.vue`（命名 PascalCase）
2. unplugin-vue-components 按 dirs 自动注册（§3.3），**无需手动配置**
3. （app 私有组件）放 `apps/<a>/src/components/`，同样在扫描 dirs 内
4. 跑 `pnpm dev` 验证 `<Xxx />` 在模板可用
5. CHANGELOG +1 + commit

### 新增 src 子目录 + alias

1. 创建 `src/<name>/` + `index.ts`
2. `packages/config/src/app-aliases.ts` 的 `createAppAliases()` 加 `'@<name>': path.join(appRoot, 'src/<name>')`（**仅此一处**，勿手改 paths）
3. 跑 `pnpm generate:tsconfig-paths` 自动写入 `"@<name>"` 和 `"@<name>/*"` 两条 paths
4. （如需要）在 main.ts 接入
5. 跑 `pnpm lint + type-check + test + build`
6. CHANGELOG +1 + commit

## 9. 验证与质量门

每个新增模块/重构完成后，**必须**跑完整套验证：

```bash
pnpm lint            # ESLint 通过
pnpm type-check      # vue-tsc 通过
pnpm test            # 208 spec 全过（2026-10-26 实测 spec 文件数；用例数以 pnpm test 输出为准，详见 docs/04 测试清单）
pnpm build           # vite build 通过
```

CI（如配置）会自动跑 husky pre-commit：

- lint-staged（prettier + eslint 自动修复）
- type-check:full（强制重建 .tsbuildinfo 缓存）
