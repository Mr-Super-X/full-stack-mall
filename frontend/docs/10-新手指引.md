## 任务 1：5 分钟环境准备 + 首次启动

### 1.1 工具检查

```bash
node -v    # 需要 >= 22.18 或 >= 24.12（package.json:engines）
pnpm -v    # 需要 >= 11.x
```

仓库根目录的 `.nvmrc` 声明了经测试的 Node 版本（22.18.0，与 `volta` 配置一致），nvm / fnm 用户 `nvm use` 或 `fnm use` 即自动切换。

版本不符时按被拦位置分两条修复路径：

- **`pnpm install` 被 `only-allow` 拦**（"This project is configured to use pnpm"）→ 系统未装 pnpm 或版本不符：运行 `corepack enable` 后重试（corepack 会按 `packageManager` 字段自动分发），或 `npm i -g pnpm@12` 手动升级
- **`pnpm install` 被 `engines` 拦**（`EBADENGINE`）→ Node 版本不符：按上一行 `.nvmrc` 切换 Node，或到 [nodejs.org](https://nodejs.org) 装 >= 22.18 LTS

其他报错（npm vs pnpm 符号链接不兼容等）看 `docs/01-工具兼容性问题踩坑记录.md`。

### 1.2 启动 dev（无需接口）

```bash
git clone <repo-url> vue3-vite-project
cd vue3-vite-project
pnpm install          # 装全 workspace 依赖
```

**登录是跨应用特性**（登录页在 `apps/auth`，admin 内已无 `/login` 路由），按目的二选一：

**路径 A · 单 app 免登录体验（最快，推荐新人首跑）**

```bash
pnpm -C apps/admin dev   # 仅起 admin（5174）；与 README 快速开始同一命令
```

先取消 `apps/admin/.env` 末尾 `# VITE_DEMO_NO_AUTH=true` 的注释（文件已在仓库内、自带引导行），浏览器访问 <http://localhost:5174/> ——守卫跳过登录/权限校验，直达 /workbench。

> 若不想依赖 mock（如离线环境）：改用 `pnpm dev:local`（local 菜单模式，菜单读本地配置不走 `/mock/menu`）。

**路径 B · 完整登录链路（跨应用漫游，测统一登录协议）**

```bash
pnpm dev:gateway      # 一体化单命令：node 网关 :8080 + 6 个 app 以 base=/<app>/ 串行起（5174-5179）
```

浏览器访问 <http://localhost:8080/admin/>，未登录由守卫整页跳 `localhost:8080/auth/login?redirect=...`，用 `admin / 123456` 登录后自动回跳原页面。

> **预期 404**：路径 A 未配 `VITE_DEMO_NO_AUTH` 时，admin 未登录会整页跳 `/auth/login`（`VITE_AUTH_ORIGIN` 缺省 `/auth`）——auth 是独立端口 5179 的 app，5174 上无此路由，**404 属预期**；统一登录全链路必须走 :8080 网关。详见 [`docs/43`](./43-Monorepo结构与开发指引.md) §5/§6 与 §9 排障。

## 任务 3：加一个完整业务页面（权限 + 异步三态 + i18n + 表单）

```bash
pnpm new-module equipment
```

### 3.2 完善 API 模块

第 2 任务已生成 `apps/admin/src/modules/equipment/apis/index.ts`（含 `EquipmentItem` 类型与 `equipmentApi.getList` 占位）。继续按业务填写：

```ts
import { request } from '@api/http'

export interface EquipmentItem {
  id: number
  name: string
  status: 'active' | 'inactive'
}

export const equipmentApi = {
  getList: (params: { page: number; pageSize: number; keyword?: string }) =>
    request<Pagination<EquipmentItem>>({
      url: '/equipment/list',
      method: 'get',
      params,
      usePageAdapter: true, // 自动按项目约定的分页协议转换
    }),
}
```

`apps/admin/src/modules/<m>/apis/index.ts` 与 `packages/shared/src/api/modules/<m>.ts` **互斥**：

- 仅本模块使用（强内聚）→ 用脚手架生成的 `apis/`
- 跨模块共享（多页面共用同接口）→ 把 `apis/` 整文件迁到 `packages/shared/src/api/modules/<m>.ts`，代码零改动

### 3.4 视图层：异步三态封装

`apps/admin/src/modules/equipment/views/List.vue`：

> 本例 API 已按 §3.2 互斥规则整文件迁至 `packages/shared/src/api/modules/equipment.ts`（共享形态，故从 `@api/modules/equipment` 引）；若保持任务 2 默认的模块本地 `apis/` 形态，则改为 `import { equipmentApi, type EquipmentItem } from '../apis'`。

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useI18n } from 'vue-i18n'
import { useRequest } from '@vv/shared' // 或由 AutoImport 自动注入，免 import
import { equipmentApi, type EquipmentItem } from '@api/modules/equipment'

const { t } = useI18n()
const keyword = ref('')

// useRequest 提供 { data / loading / error / isEmpty / refresh / cancel } 三态封装
const { data, loading, error, isEmpty, refresh } = useRequest(
  () => equipmentApi.getList({ page: 1, pageSize: 20, keyword: keyword.value }),
  { watch: [keyword] } // 关键词变化自动重拉
)

const rows = computed<EquipmentItem[]>(() => data.value?.list ?? [])
</script>

<template>
  <AsyncState :loading="loading" :error="error" :is-empty="isEmpty" @retry="refresh">
    <!-- 关键表格组件，从 packages/ui/src/components/common/ 找通用封装（unplugin 自动注册，模板直接用） -->
    <el-table :data="rows">
      <el-table-column :label="t('equipment.name')" prop="name" />
      <el-table-column :label="t('equipment.status')" prop="status" />
    </el-table>
  </AsyncState>
</template>
```

### 3.7 命令式弹窗：useConfirm / useDialog

**二次确认**（删除 / 重置 / 批量清空等危险操作）：

```ts
async function handleDelete(id: number) {
  // 一行 API，取消 resolve false（无须 try/catch）
  if (!(await useConfirm({ content: `确定删除设备 ${id} 吗？此操作不可恢复。`, danger: true })))
    return
  await equipmentApi.remove(id)
  ElMessage.success('已删除')
}
```

**渲染自定义内容组件**（如编辑表单弹窗）：

```ts
const editDialog = useDialog(EditForm, { title: '编辑设备', width: '600px' })

async function openEdit(id: number) {
  try {
    await editDialog.open({ id }) // 点「确定」resolve；取消 reject DialogCancelledError
    ElMessage.success('已保存')
  } catch (e) {
    if (e instanceof DialogCancelledError) return // 取消/关闭/X/ESC/遮罩
    ElMessage.error(`异常：${String(e)}`)
  }
}
```

完整说明：[`docs/27-ProDialog使用指南.md`](./27-ProDialog使用指南.md) §3（useDialog）+ §5.2（useConfirm）。

### 3.8 使用项目封装（ESLint + 规范双轨）

业务代码（`apps/<a>/src/**`）必须走项目封装，禁止直接调用底层 API。约束分两层，不要误以为全是 ESLint 兜底：

- **ESLint 硬约束**（`no-restricted-imports` warning + IDE 实时提示）：仅下表 2 条
- **规范 + code review 兜底**：`useAuth`（权限）/ `useDialog`（命令式弹窗）/ `useConfirm`（二次确认）暂无 ESLint 规则（DS-8 披露，见 [CLAUDE.md](../CLAUDE.md) §1.5）——review 时按同一标准把关

| 禁止                                     | 推荐替代                                                                                            |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `import { useRouter } from 'vue-router'` | `useAppRouter`（`@vv/shared` 自动注入；显式 import 走 `import { useAppRouter } from '@vv/shared'`） |
| `import axios from 'axios'`              | `useRequest`（`@vv/shared` 自动注入；显式 import 走 `import { useRequest } from '@vv/shared'`）     |

**为什么这样设计？**

- `useAppRouter` 集中错误处理（toast）、i18n title 写入、类型安全的按 name 跳转、history fallback
- `useRequest` 统一三态管理（loading / error / empty）、请求竞态保护、AbortController
- 直接调用底层 API 会绕过这些保护，埋下运行时 bug

**白名单位置（天然不受限制）：**

- `packages/shared/src/composables/**`（封装自身实现）
- `apps/<a>/src/router/**`（路由注册；守卫实现本体在 `packages/shared/src/router-guards/`）
- `apps/<a>/src/plugins/**`（插件初始化）
- `apps/<a>/src/main.ts`、`apps/<a>/src/App.vue`
- `*.spec.ts`（测试用例）

> `useRoute`（读取当前路由状态）不在拦截范围，vue-router 的只读 API 业务侧有持续需求。

## 任务 4：调常见问题

### 问题 A：401 不停刷新，登录后没法调通

**症状**：每次调接口都触发 `token-refresh`，刷新后又 401，循环。

**排查**：

```bash
# 1. 看后端返回的 status code
#    Chrome DevTools → Network → 看 /api/auth/refresh 的 response
# 2. 看前端拦截器走的是哪条分支
```

**代码路径**：

- `packages/shared/src/api/http.ts` 的 `request<T>()` 自动捕获 401 + `!config._retried` 触发 refresh
- 第二次 401 → `performLogout()` → toast + 清会话 + 整页回跳 `${VITE_AUTH_ORIGIN}`（缺省 `/auth`）
- 检查 `packages/shared/src/api/token-refresh.ts` 的 `refreshSession()` 并发去重逻辑（refreshingPromise 单飞保证，同一时刻仅一个 refresh 在途）

**对照清单**：

- [ ] `pnpm dev` / `pnpm dev:local` 均处于开发模式，Mock 由 `@vv/config` 工厂自动启用；`dev:local` 只切换菜单来源为 local
- [ ] `packages/mock/src/auth.ts` 的 `permissions` 是否包含本页面所需权限码

### 问题 B：主题切换不生效 / 双主题布局错乱

**症状**：调用 `useTheme().setMode('dark')` 后颜色没变，或局部元素没切换。

**排查**：

1. 自定义元素是否用了 `var(--bg-*)` 等主题感知变量？参考 `docs/06-主题管理规范.md` 速查表
2. 主题 store 是否被持久化？清 `localStorage['<VITE_APP_ID>:theme-mode']` 后重试（persist key = `${VITE_APP_ID ?? 'app'}:theme-mode`，各 app 独立命名空间，如 admin 为 `admin:theme-mode`；详见 `packages/shared/src/store/modules/theme.ts` 与 docs/19 §4.4）
3. Element Plus 组件需要 CSS 变量覆盖，看 `packages/ui/src/assets/styles/element-overwrite/`（目录）

### 问题 C：远程菜单 404，sidebar 看不到新页面

**症状**：登录成功但 sidebar 没出现预期菜单项。

**排查顺序**：

```
1. DevTools Network 看 /api/menu 响应
   ↓ 200 + 列表里有你的模块 → 继续
   ↓ 404 → 打开 apps/admin/src/router/config.ts 看菜单模式（remote / local）
                ↓
       remote 时需要 mock 路由：packages/mock/src/menu.ts 配一下
       local  → 直接看 apps/admin/src/router/auto-register.ts 自动注册结果

2. pnpm check:routes 一致性校验（type / whitelist / 路由 三处）

3. 组件权限被拒绝？v-permission 把整页 hide 了？

4. 菜单项 hidden=true？后端菜单协议的 hidden → 前端 meta.visible:false
```

### 问题 D：API 数据格式不对（分页 / 时间戳 / 字段名）

**症状**：后端返回 `{ records: [...], total: 100 }`，前端期望 `{ list: [...], total: 100 }`。

**解决**：

```ts
// packages/shared/src/api/page-adapter.ts 提供可配置的字段映射
configurePaginationAdapter({
  request: { pageField: 'pageNum', pageSizeField: 'pageSize' }, // 请求字段名
  response: { listField: 'records', totalField: 'total' }, // 响应字段名
})
```

调用 `request<T>({ ..., usePageAdapter: true })` 即可双向转换。

### 问题 E：本地能跑但 build 后页面 404

**症状**：`pnpm dev` 一切正常，`pnpm -C apps/admin build-only && pnpm -C apps/admin preview` 后访问某页面 404。

**根因**：静态托管未配置 SPA fallback（history 模式下所有 404 应 fallback 到 `/index.html`）。

**修复**（Nginx 示例）：

```nginx
location / {
```

## 任务 5：提交首个 PR（提交前三门禁速查）

前 4 个任务都在本地闭环；本任务把改动推到远端前的**最小验证集**固化成习惯——
CI 有 19+ 个 step，但提交前本地只要跑三门禁就能拦截 90% 的红：

```bash
pnpm lint          # ESLint 全仓（含 package-contract 边界规则，--max-warnings 0）
pnpm type-check    # turbo 各 app vue-tsc（增量；全量用 pnpm -C apps/admin type-check:full）
pnpm test          # turbo 拓扑序全量单测
```

三条约定（违反会被 review 打回）：

1. **中文 commit message**，格式 `type(scope): 描述`（type ∈ feat/fix/refactor/docs/test/chore/perf/ci）
2. **功能性变更同步 `CHANGELOG.md`「未发布」段**（纯 typo 免记）
3. 新增 composable / store / 类型必须带 `.spec.ts`（覆盖率门禁 ≥80%）

推上去之后 CI 会自动跑完整门禁集（路由一致性 / 别名一致性 / mock 接线 / 文档硬数据 /
网关 smoke / e2e 等），红了的修复映射见 [docs/46-CI门禁速查.md](46-CI门禁速查.md)。
